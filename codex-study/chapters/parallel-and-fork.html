聊天分支（Fork）與工作樹（Worktree）隔離

區分新聊天、聊天分支（Fork）與工作樹（Worktree）隔離，再了解移交（Hand off）的時機。

05

什麼時候分開聊

一則聊天處理一個明確的結果。當出現兩個獨立方向時，可以開兩則聊天平行處理，不必把所有要求都塞進同一個對話裡。

點擊頂部或側邊欄的「新增聊天」按鈕適合獨立的新任務；聊天分支（Fork，或在對話框輸入 /fork）則適合已經有一段討論，想從其中某個時間點換個方向繼續推進。

從某則訊息建立聊天分支（Fork，/fork）

  1. 找到希望保留的那段上下文

    回到一則已經完成的回答末尾，找到「分支到新聊天」按鈕（或在輸入框輸入 /fork）。選擇哪一則回答，就決定了從哪裡建立分支推進。

  2. 選擇分支的執行位置

    點擊後，依需求選擇「在此工作空間中建立分支（/local）」，或針對 Git 專案選擇「在新工作樹中建立分支（/worktree）」。

  3. 在新聊天中繼續

    開啟新出現的聊天，檢查保留下來的上下文，再發送新的要求。

新聊天會保留分支點之前的對話上下文；分支點之後在原聊天新增的訊息，不會自動同步到新分支。

所有對話都可以重新命名，包括一般新聊天、原聊天與分支聊天。可從聊天選單選擇「重新命名」，或在支援的版本使用 /rename；名稱寫清楚工作方向，之後會更容易找到。

聊天獨立，檔案未必獨立（三種平行層次）

聊天分支不等於 Git 分支。如果選擇「在此工作空間中建立分支」，兩則聊天仍會讀寫同一個本機資料夾。一邊修改檔案，另一邊就會讀到這些變動。為了避免衝突，你可以依情境選擇平行分工方式：

  • 同資料夾讀寫分工（Free / Plus 皆可用）：一則聊天只負責分析與規劃，另一則負責實際修改；或兩則分別處理不同檔案並事先界定範圍。
  • 本機 Git 工作樹（Worktree）隔離（/worktree，Free / Plus 皆可用）：讓不同聊天在各自獨立的 Git 工作樹副本中平行修改程式碼，彼此互不覆蓋，完成後再檢視與合併。
  • Codex 雲端任務（Cloud）平行沙盒：若帳號已開放雲端入口，且專案已連結支援的儲存庫，可在獨立雲端環境執行任務；實際方案權益、資源與可用性以目前帳號及官方方案頁為準。
雲端環境依帳號目前顯示的資源選擇

雲端任務的可用性與資源規格可能依方案、工作區及設定不同。建立前查看當前畫面，不以舊截圖推定固定記憶體容量。

工作樹（Worktree）移交（Hand off）與 .worktreeinclude

在桌面版使用本機 Git 工作樹（Worktree）平行開發時（Free 與 Plus 皆內建支援），有兩項進階功能：

  1. 在本機（Local）與工作樹（Worktree）間移交（Hand off）：
    • 點擊聊天標題列的「在此建立分支（Create branch here）」，可將處於 Detached HEAD 狀態的工作樹轉為正式 Git 分支並直接 Commit / Push。
    • 想在自己習慣的本機 IDE 或開發伺服器測試工作樹（Worktree）的成果時，點擊標題列的「移交（Hand off）」並選擇 Local。反之，本機做到一半也可使用移交（Hand off）切到背景工作樹（Worktree）繼續；操作後核對實際工作目錄與檔案差異。
  2. 需要時用 .worktreeinclude 複製本機檔：

    Git 未追蹤的本機檔案預設不會進入新工作樹（Worktree）。若測試必須使用某個非敏感設定檔，可先確認內容與目的，再在專案根目錄的 .worktreeinclude 列出相對路徑。不要把真實金鑰、Token 或生產資料列入教學範例；這些資料應走專案核准的秘密管理方式。

工作樹（Worktree）快照（Snapshot）與永久工作樹

Codex 預設在 $CODEX_HOME/worktrees 保留最近 15 個受管工作樹（可於「設定 → Worktrees」調整）。當聊天封存或超過上限時，系統會先儲存一份快照（Snapshot）再清理空間，日後重新打開聊天可一鍵還原；若需要長期保留且供多則聊天共用的環境，可從專案選單建立「永久工作樹（Permanent worktree）」。
