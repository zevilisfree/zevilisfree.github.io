規劃（Plan）、目標（Goal）與排程任務

用規劃（Plan）討論做法、目標（Goal）追蹤結果，並確認排程任務的執行條件。

規劃（Plan）：先討論做法（/plan）

需求模糊、步驟多或涉及多個檔案時，先使用規劃（Plan）模式討論做法；簡單且明確的任務可直接描述。若你的帳號提供此功能，可點擊輸入框左下角「＋」選擇「規劃模式」，或輸入 /plan。進入後，輸入區可能顯示「方案」標籤，表示這則聊天正在討論規劃。

可以這樣說
先不要執行。請先和我確認目標、範圍、輸入素材、交付格式與驗收標準。
有需要我決定的地方請逐項問清楚，然後提出實作方案。

Codex 可能會用互動選項卡片詢問你的偏好，也可能直接提出問題。如果推薦選項不合適，可以直接補充自己的答案，不必硬選。

拿到規劃（Plan）方案後，請重點檢查：要做什麼、不做什麼、會改動哪些檔案、如何驗收。確認無誤後，再使用畫面提供的執行入口，或明確要求開始實作。

規劃（Plan）模式期間仍可能會讀取檔案、檢查現況；它並不是「完全不使用任何工具」。但請注意，不要把討論做法當成已經授權正式修改。

目標（Goal）：圍繞結果推進（/goal）

點擊「＋」選擇「目標」，或輸入 /goal，即可使用目標（Goal）模式。請給出可以用來判斷是否完成的具體結果，而不只是說「幫我研究一下」。請寫清楚三個要素：

  1. 結果：最終要交付什麼產出。
  2. 範圍：允許處理哪些內容，哪些東西不能動。
  3. 完成條件：如何證明已經全部做完（例如通過所有單元測試且無 Lint 錯誤）。

任務啟動後，輸入框上方會出現目標狀態列，可以隨時暫停、繼續或調整目標，也可搭配第 3 章的 /side 支線聊天在不打斷任務的情況下詢問進度。

目標（Goal）模式會持續尋找下一步，但這不代表它可以越權操作，也不保證任何目標都能自動達成。當缺少資料、需要你做決定、或是額度與環境受限時，它仍然會停下來等待。

排程任務：固定時間與 App 事件觸發

當某項工作已經手動跑通並確認穩定後，才適合安排重複執行。排程是否可用依方案、工作區與目前版本而定；先查看左側是否顯示「已排程」。你可以直接在聊天中說明要做什麼、什麼時候做：

建立排程任務
每週五台北時間 18:00，依照已經確認的流程整理一份本機摘要。
只讀取指定資料，結果儲存在目前的專案中。
不要對外發送或發布；若缺少輸入資料時請說明缺少什麼。

建立後，請到左側「已排程」中核對設定，並善用以下三項進階能力：

  • 選擇「本機（Local）」或「背景工作樹（Worktree）」隔離執行：在 Git 專案中，可設定讓排程任務跑在獨立的背景工作樹（Worktree）中，避免定時任務執行時干擾你正在本機修改到一半的檔案。
  • 獨立執行 vs. 同聊天續跑（支援自訂 RRULE）：可選擇每次建立獨立執行紀錄或延續同一則聊天；進階週期支援直接編輯 RFC 5545 RRULE 規則。
  • App 事件觸發任務（Event-triggered tasks）：符合資格的網頁版與行動版帳號可依 Gmail 新郵件、Slack 指定頻道訊息或 GitHub Pull Request 活動觸發。須先連接並授權服務；同一任務可設多個事件觸發，但不能同時設定事件觸發與定時排程。桌面版目前以時間排程為主。
本機任務需要電腦保持開機連線

需要存取本機檔案的排程任務，必須保持電腦開機且應用程式持續執行（可在設定開啟 Prevent sleep while running 防止執行中休眠）。一旦電腦關機、休眠或網路中斷都會影響執行。

雲端執行與本機排程的差異

執行環境建立前確認任務會在哪裡執行

存取本機檔案的排程須讓電腦與應用程式保持運作。若你的帳號提供雲端執行選項，雲端任務能在不同環境運行，但可讀取的檔案與工具會不同。依建立畫面的執行環境與權限說明選擇，不要因為訂閱名稱就假設任務會自動搬到雲端。

規劃（Plan）、目標（Goal）與排程的差異

規劃（Plan）用來先擬定做法；目標（Goal）用來圍繞完成條件持續推進；排程任務則依時間或事件再次執行。

開啟目標（Goal）不會自動建立每週排程，寫好技能（Skill）也不會自動開始定時執行。需要哪一項功能，就個別確認該功能已經設定完成。
