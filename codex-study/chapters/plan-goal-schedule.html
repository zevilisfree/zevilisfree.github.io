規劃（Plan）、目標（Goal）與排程任務

用規劃（Plan）對齊做法、目標（Goal）圍繞驗收條件推進，並掌握排程任務、Dots 雲端代理、Sites 網站部署與 Space 協作空間。

規劃（Plan）：先對齊做法與邊界再動手（/plan）

當需求較模糊、步驟繁多或涉及跨模組修改時，直接讓 AI 開始寫扣往往會偏離預期。這時請先點擊輸入框左下角「＋」選擇「規劃模式」，或輸入 /plan。進入後，輸入區會顯示「方案」標籤，代表當前對話處於規劃階段。

可以這樣說
先不要修改程式碼。請先讀取相關檔案，和我確認目標、範圍、輸入素材、交付格式與驗收標準。
有需要我決定的架構或邊界問題請逐項問清楚，最後提出分步實作方案。

在規劃（Plan）模式中，Codex 仍會主動讀取專案檔案、搜尋符號與檢查現況（並非完全停用工具），但它會先把重心放在理解問題，並透過互動式選項卡片（Multiple-choice Cards）向你確認關鍵技術決策。如果預設選項不合適，可直接在卡片底部的「否，並告訴 ChatGPT 該如何改進」輸入欄補充自己的想法，或點擊「跳過」。

拿到規劃方案後，請重點檢查四件事：要做什麼、明確不做什麼（Non-goals）、預計改動哪些檔案、如何執行測試驗收。確認無誤後，再點擊畫面提供的執行按鈕或明確下令開始實作。

目標（Goal）：圍繞可驗證結果自主推進（/goal）

點擊「＋」選擇「目標」，或輸入 /goal，即可啟用目標（Goal）模式。一般對話每完成一輪就會停下來等你指示；而 Goal 模式會讓 Codex 圍繞你設定的最終判準，自動迭代「修改 → 執行測試 → 修復錯誤 → 再次驗證」直到達標。設定 Goal 時請務必寫清楚三個要素：

  1. 交付成果（Deliverable）：最終要產出什麼具體功能、檔案或報告（避免只寫「幫我研究一下」這類沒有終點的描述）。
  2. 修改邊界（Scope）：允許修改哪些目錄與模組，哪些受保護檔案或公開 API 絕對不能動。
  3. 完成判準（Done-when Criteria）：如何用客觀證據證明已經做完（例如：pytest 全部通過、python build_search_index.py --check 回傳 0、無未處理的型別或 Lint 錯誤）。

任務啟動後，訊息下方會標示「🎯 已設為目標」，輸入框上方則會常駐「🎯 進行中的目標」狀態列，你可隨時點擊右側的暫停（⏸）、刪除或展開按鈕，或輸入 /goal pause、/goal resume 控制節奏。

💡 社群黃金工作流：/plan → /goal → /side 三連技

處理大型重構或複雜功能時，資深開發者最推薦的組合技是：
第一步（/plan）：先用規劃模式讓 Codex 探索程式碼並透過選項卡鎖定架構與驗收清單。
第二步（/goal）：計畫確認後，開啟 /goal 要求「嚴格依照上方確認的方案實作，並持續跑測試修正直到所有驗收條件通過」。
第三步（/side）：在 Goal 長時間推進期間，若你想確認某個函式細節或詢問進度，按 Ctrl+Alt+S（或輸入 /side）開啟支線聊天提問，完全不會打斷主線 Goal 任務，也不會把臨時問答塞進主對話 Context！

請注意：目標（Goal）模式會持續尋找下一步，但不會因此繞過你的沙盒或權限核准規則。當遇到需要額外授權的操作、缺少關鍵決策資訊或達到速率限制時，它仍會安全停下並等待你指示。

排程任務：定時執行（RRULE）與 App 事件觸發（Event-triggered）

當某項工作已經手動跑通並確認提示詞與技能穩定後，才適合交給排程自動執行。請先查看左側導覽列是否顯示「已排程（Scheduled）」，或直接在聊天中描述排程條件：

建立排程任務
每週五台北時間 18:00，依照已經確認的流程整理一份本機專案變更與待辦摘要。
只讀取指定資料夾，結果儲存在目前的專案 reports/ 目錄中。
不要對外發送或發布；若缺少輸入資料時請說明缺少什麼。

建立後，請到左側「已排程」面板核對設定，並善用以下三項進階控制能力：

  • 選擇「本機（Local）」或「背景工作樹（Worktree）」隔離執行：在 Git 專案中，強烈建議將排程任務設為跑在獨立的背景工作樹（Worktree）中，避免定時任務啟動時干擾你正在主工作目錄修改到一半的檔案。
  • 獨立執行 vs. 同聊天續跑（支援自訂 RFC 5545 RRULE）：可選擇每次觸發時建立全新獨立執行紀錄，或延續同一則聊天累積上下文；進階週期設定支援直接編輯標準 RFC 5545 RRULE 規則（例如每月最後一個工作天或每週一三五）。
  • App 事件觸發任務（Event-triggered tasks）：符合資格的網頁版與行動版帳號可根據外部應用程式事件自動觸發任務，例如 Gmail 收到符合條件的新郵件、Slack 指定頻道訊息或 GitHub Pull Request 活動。使用前須先完成連接器授權；同一任務可綁定多個事件觸發條件，但不能在同一個任務上同時混用「事件觸發」與「固定時間排程」（桌面版目前以時間排程為主）。
本機排程需要電腦保持開機連線

需要存取本機檔案的排程任務，必須保持電腦開機且桌面版應用程式持續執行（建議在 Windows 系統電源設定調整睡眠時間，或於「設定 → 連線 → 控制此電腦」開啟「保持此電腦喚醒」防止接上電源與啟用遠端存取時進入睡眠）。一旦電腦關機、休眠或網路中斷，本機排程就會暫停直到恢復連線。

進階雲端代理與工作區協作：Dots、Sites 與 Space

除了本機的 /plan、/goal 與排程任務外，最新一代 ChatGPT 與 ChatGPT Work 生態系提供了三大雲端自主與協作基石，讓你能把工作延伸到全天候雲端代理、互動網頁部署與即時團隊文件：

1. Dots（@DotName）：全天候運作的雲端自主代理

Dots（官方文件）是駐留在雲端、可 24/7 全天候運作的自主代理，底層由 GPT-6 Astra 驅動，並配備專屬的雲端電腦與瀏覽器環境：

  • 長期職責導向（Ongoing Responsibilities）：一般聊天與 /goal 適合處理單次任務；而 Dot 則是為了「長期持續負責某項職能」而設計（例如：每日追蹤競品動態、監控特定 GitHub 儲存庫 PR 與安全警報、彙整跨部門進度週報）。每個 Dot 都有專屬名稱與 @DotName 識別碼。
  • 多頻道雙向整合（Slack & Microsoft Teams）：除了在 ChatGPT 對話或 Space 頁面中直接用 @DotName 呼叫外，你還可以將 Dot 連接至團隊的 Slack 或 Microsoft Teams 頻道，讓團隊成員直接在通訊軟體中與 Dot 協作。
  • 嚴格的跨頻道隱私與核准邊界：為了防止機密外洩，當 Dot 需要執行具外部影響的動作，或準備將來自私人對話／受限來源的資訊張貼到公開或多人共用頻道時，系統會強制停下來向你發出核准請求（Approval Request），經你確認後才會發送。

2. ChatGPT Sites（@Sites）：建置、預覽與託管全端互動網站

ChatGPT Sites（官方文件）讓你直接在對話中點名 @Sites（或從左側 Sites 入口）建置、即時預覽並一鍵部署互動式網站、資料儀表板、內部小工具與表單應用：

  • 內建雲端資料庫與物件儲存（.openai/hosting.json）：Sites 不只是靜態網頁！透過專案中的 .openai/hosting.json 宣告式設定檔，網站可直接綁定內建的 D1 關聯式資料庫（SQLite 相容）與 R2 物件儲存空間，輕鬆打造具備持久化資料讀寫能力的內部系統。
  • 內建訪客認證與 5 級發佈權限控制：支援啟用 Sign in with ChatGPT 驗證訪客身分，並提供五種精細的發佈存取層級：① 僅限自己（Only me）、② 指定邀請名單（Specific people）、③ 外部訪客（External guests，透過信箱驗證）、④ 工作區全體成員（Anyone in workspace，適用於 Business / Enterprise）、⑤ 公開網際網路（Public on the web）。

3. ChatGPT Space 與 Pages：取代舊版媒體庫的即時協作中樞

ChatGPT Space（官方文件）已正式取代舊版的個人媒體庫（Library），成為整合檔案、生成媒體與即時文件的統一工作區中樞：

  • 區塊式即時協作文件（Pages）：Space 內建支援多層子頁面（Subpages）的 Pages 編輯器。你可以把任何一則精彩的 ChatGPT 回覆一鍵轉存為 Page，並在文件內輸入 / 插入排版區塊，或輸入 /visualize 將數據即時轉為互動式圖表與計算機。
  • 真人與 AI 同場協作（Multi-user & Multi-agent）：在共享的 Page 中，你可以同時用 @同事名稱 標註團隊成員，並用 @ChatGPT 或 @DotName 請 AI 直接在文件段落旁協同撰寫、潤稿或補充研究數據。
  • 個人記憶隱私保護：在多人共享的 Space Page 中呼叫 AI 時，系統絕不會將你個人的 ChatGPT 帳號記憶（Personal Memories）暴露給其他協作者，除非你主動將內容寫入公開文件段落中。
執行環境建立任務前，務必區分「本機執行」與「雲端執行」

需要存取你電腦上未推送檔案的排程任務，必須在本機（Local / Worktree）執行並保持電腦開機；而 Dots、雲端事件觸發任務與 Codex Cloud 任務則是在 OpenAI 的雲端隔離容器中運行，不需要你的電腦保持開機，但它們只能存取已授權連接的雲端儲存庫與連接器。請依建立畫面的執行環境說明選擇，不要單憑訂閱方案名稱就假設本機任務會自動搬到雲端。

一張表看懂：Plan、Goal、排程任務與 Dots 的分工

這四項功能分別解決不同維度的問題，實務上可以自由串聯搭配：

功能名稱核心定位何時結束或再次啟動？最佳適用場景
規劃模式（/plan）動手前先探索現況、透過選項卡釐清需求並鎖定實作藍圖。產出確認版方案並交由你核准實作時結束。需求模糊、跨多檔案修改、需要先對齊架構與邊界時。
目標模式（/goal）圍繞明確的「完成判準（Done-when）」在單次工作階段內自主迭代測試與修復。達成所有驗收條件、需要你決策或被手動暫停時停止（不會自動變每週排程）。大型功能開發、全站巡檢修正、跑通整套自動化測試套件。
排程與事件任務（Scheduled / Event）將已驗證穩定的流程，依固定時間（RRULE）或外部事件（Gmail / Slack / PR）自動重跑。每次時間到達或事件觸發時執行一輪。每日晨間郵件與行事曆簡報、每週五固定程式碼健康檢查、PR 事件自動處理。
雲端代理（Dots）配備專屬雲端電腦與瀏覽器（GPT-6 Astra）、24/7 待命的常駐職能代理。長期持續運作，可隨時在 ChatGPT、Space、Slack 或 Teams 中以 @DotName 互動。跨部門進度追蹤、全天候競品與安全情報監控、團隊頻道常駐 AI 助手。
