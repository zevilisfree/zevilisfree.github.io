五大擴充與分工概念：Skill、Plugin、MCP、Hooks 與 Subagents

在 2026 年 10 月的最新架構中，OpenAI 已將過去分散的「連接器（Connectors / Connected Apps）」統一整合進外掛程式（Plugins）生態系。先透過下表分清楚這五個核心擴充與分工概念各自負責什麼：

名稱與呼叫入口核心作用與觸發機制設定檔或儲存位置
技能（Skill）
輸入 $技能名稱 或 /skills		將一項工作的標準步驟、提示範本、參考文件與輔助腳本封裝成可重複使用的套件。支援漸進式自動觸發（Implicit invocation）與手動點名呼叫。桌面版左側「自訂 → 技能」；個人全域：~/.agents/skills/<name>/SKILL.md、專案：.agents/skills/<name>/SKILL.md
外掛程式（Plugin）
輸入 @外掛名稱 或 /plugins		統一的打包安裝單位（涵蓋舊稱 Connectors / Apps）。一個外掛內可同時包含雲端服務連線（如 Google Drive、Gmail、Slack、GitHub）、多組 Skills、MCP 伺服器與 Hooks。桌面版左側「自訂 → 外掛程式」（或「設定 → 外掛程式」），以及 CLI 輸入 /plugins 安裝與啟停。
模型上下文協定（MCP）
輸入 /mcp 或 codex mcp		開放標準協定，讓 Codex 安全連接本機工具（stdio）或遠端 API／資料庫伺服器（streamable_http + OAuth）。~/.codex/config.toml 或專案 .codex/config.toml 的 [mcp_servers.<name>]
事件掛鉤（Hooks，介面譯為「掛勾」）
輸入 /hooks 檢視與信任		在代理執行生命週期的 5 個關鍵節點（如執行指令前 PreToolUse、改檔後 PostToolUse）自動觸發的決定性腳本，可用於強制跑 Linter 或攔截危險指令。桌面版「設定 → 程式設計 → 掛勾」；全域：~/.codex/hooks.json、專案：.codex/hooks.json
子代理（Subagents，介面亦譯為「子智慧體」）
輸入 /subagents 管理		由主代理派發、擁有獨立上下文視窗與獨立沙盒權限的分工代理（如唯讀研究員、安全審查員、測試修復員），只將精簡結論回傳主對話，避免塞爆主對話 Context。於 config.toml 啟用 multi_agent = true，角色定義於 ~/.codex/agents/ 或 .codex/agents/*.toml

初學者不必一開始就手動寫 JSON 或 TOML 設定檔。只要官方外掛目錄已提供現成入口，先從桌面版左側「自訂 → 外掛程式」一鍵安裝即可；當你需要為團隊打造自動化防線時，再參考下方的進階設定範例。

安裝外掛程式（Plugins）、連接雲端辦公服務與使用 ChatGPT 登入

從最左側導覽列進入「自訂 → 外掛程式」或「技能」，先看目前帳號的「已安裝」清單與「公開／個人」分頁。外掛在 Chat、Work、Codex 的可用性及動作範圍可能不同；在要使用的模式中檢查是否顯示、是否完成帳號連線，以及外部服務授權。若 Work 可用 @Google Drive 等外掛，先從非敏感資料做唯讀練習。

桌面版與 CLI 安裝及驗證步驟

  1. 在左側進入「自訂 → 外掛程式」（或在 Codex CLI 輸入 /plugins），搜尋需要的名稱，點開詳細資料，確認提供者、會讀取的資料及能執行的動作。
  2. 按安裝按鈕；若畫面顯示「啟用」，也確認外掛程式及所需技能已啟用。
  3. 需要使用外部服務時，依畫面連結帳號（支援 使用 ChatGPT 登入 Sign in with ChatGPT 或 OAuth 授權），逐項檢查要求的權限與資料範圍（請記住：外掛程式安裝成功不等於外部帳號已連線）。
  4. 開啟新對話，在輸入框用 @外掛名稱 或 $技能名稱 明確點名，執行上表的小練習並核對實際輸出。
安裝與連線前看權限與資料訓練政策

外掛程式（Plugins）、連接器與 MCP 工具有各自的存取範圍；本機命令的沙盒與斷網限制不會自動套到外部雲端工具。此外請留意：Business、Enterprise 與 Edu 方案透過外掛程式與連接器讀取的資料預設絕不用於訓練模型；而 Free、Go、Plus 與 Pro 個人方案則依你在「設定 → 資料控制」中的「協助改善所有人的模型體驗」開關而定。官方外掛與隱私說明 · 官方權限說明

工作區政策可安裝項目依帳號與管理設定而異

個人帳號可從目前介面查看可用的外掛與技能；Business、Enterprise 與 Edu 工作區還可能由管理員限制第三方外掛和 MCP 伺服器，並提供內部專屬目錄（Private plugin registry）。

第三方技能：初學者與開發者先看哪幾個？

以下是依 2026-10 兩個作者的公開倉庫與社群實戰評價所做的選用建議，屬第三方內容。你可以先閱讀其設計理念（甚至直接用內建的 $skill-creator 為自己的專案打造類似技能），確認適合自己的任務再決定是否安裝：

  • 動手前先拷問規格（grill-me）：Matt Pocock 的 grill-me 會在寫任何一行程式碼或文件前，先自主掃描專案現況，再針對模糊需求以「決策樹＋推薦選項」一輪一輪反問你，直到所有邊界條件毫無死角才產出實作計畫；不寫程式的商業規劃同樣極為好用。
  • 長任務跨對話完美交接（handoff）：Matt Pocock 的 handoff 會在長對話 Context 快滿或準備下班交接時，自動盤點目前 Git Diff、已確認需求、已完成事項與下一步指令，產生結構化交接文件供新聊天秒速接手（此技能預設會寫入系統暫存目錄，使用前先確認儲存位置與內容）。
  • 紅燈先行除錯法（diagnosing-bugs）：diagnosing-bugs 嚴格規定「沒有建立可重現錯誤的自動化檢查指令（Red test），絕對不准進入修改程式碼階段（No Phase 2）」，徹底杜絕 AI 憑感覺盲目亂改。
  • 極簡標準庫優先（Ponytail）：Ponytail 強調優先複用既有程式碼、標準函式庫與最小可行修改。初學者可先用 lite 模式體驗；完成後仍要檢查需求、測試、安全與可讀性。

安裝第三方倉庫前先看範圍：Matt Pocock 的安裝方式會加入整組技能；而 Ponytail 的完整外掛除技能外還包含生命週期 hooks。若選擇含 hooks 的完整外掛，務必先在 /hooks 檢視實際執行的本機命令後，再決定是否標記為信任（Trusted）。Codex 官方 hooks 說明

把流程做成技能（Skill）：SKILL.md 目錄結構與漸進式載入

當你發現自己第 3 次輸入相似的長篇工作流要求，且已經手動跑通確認步驟穩定時，就可以呼叫內建的 $skill-creator（在 ChatGPT 對話中亦可輸入 @skill-creator）將它封裝成可重複使用的標準技能：

用 $skill-creator 建立技能
使用 $skill-creator，把我們剛才確認過的流程整理成一個可重複使用的技能。
寫清楚需要哪些輸入、依什麼步驟處理、輸出格式與檢查方法。
不要包含帳號、金鑰、個人路徑；遇到缺少資料或需要對外發送時，先停下來向我確認。

進階選讀：SKILL.md 標準規範與漸進式載入（Progressive Disclosure）原理

根據 官方 Skills 架構文件，一個標準技能是一個獨立資料夾，個人跨專案共用技能放在 ~/.agents/skills/<skill-name>/（或 ~/.codex/skills/），專案專屬技能則放在儲存庫的 .agents/skills/<skill-name>/（或 .codex/skills/，可隨 Git 與團隊共享）。

  • 為什麼裝很多技能不會塞爆 Context？因為「漸進式載入」！Codex 啟動工作階段時，只會讀取每個技能 SKILL.md 最上方的 YAML frontmatter（name 與 description）；只有當你的任務需求符合某個技能的 description（隱式自動觸發），或你主動用 $skill-name 點名時，才會把完整的 SKILL.md 正文以及同目錄下的 scripts/、references/、assets/ 載入上下文。
  • 撰寫 SKILL.md 的黃金法則：資料夾名稱必須與 YAML 中的 name 完全一致（僅限小寫英文字母、數字與連字號 -）；而 description 則是自動觸發的靈魂，必須同時寫清楚「這個技能做什麼」以及「在什麼關鍵字或情境下應該觸發／不該觸發」：
.agents/skills/pr-release-note/SKILL.md 標準結構範例
---
name: pr-release-note
description: 根據兩個 Git 分支或標籤之間的提交歷史與變更差異，產出繁體中文版更說明（Release Notes）。當使用者要求整理版本更新日誌、發布說明或變更摘要時觸發；不適用於單一未提交檔案的日常 Code Review。
---

# 版本發布說明產生流程

1. 先執行唯讀指令 `git log <base>..<head> --oneline` 與 `git diff --stat <base>..<head>` 確認變更範圍。
2. 將變更分類為：「新增功能」、「問題修正」、「安全性與權限調整」與「破壞性變更（Breaking Changes）」。
3. 輸出至指定檔案前先展示草稿，絕不自動執行 git tag 或發布動作。

進階工程自動化：Hooks 生命週期防線、MCP 設定與 Subagents 子代理分工

當你想讓 Codex 在大型專案中做到「改完檔案自動跑 Linter、危險指令自動攔截、跨系統查資料庫、平行派發多個子代理同時研究」，可善用以下三大進階機制：

1. 事件掛鉤（Hooks）：用 hooks.json 打造零遺漏的自動化品管

Hooks 允許你在全域 ~/.codex/hooks.json 或專案 <repo>/.codex/hooks.json 設定本機檢查腳本（專案級 Hooks 首次載入或修改後，需在對話輸入 /hooks 檢視實際命令並標記為 Trusted 才會生效，防止惡意儲存庫自動執行腳本）。官方支援五大生命週期事件：

  • SessionStart：對話啟動、恢復或執行 /compact 壓縮後觸發；腳本的 stdout 輸出可自動注入對話作為額外環境背景（例如在 /compact 後自動重新注入核心架構摘要，防止壓縮失憶）。
  • UserPromptSubmit：使用者送出訊息前觸發，可用於檢查是否誤貼入機密格式。
  • PreToolUse：代理執行工具（如 Bash 指令）前觸發。若檢查腳本回傳退出碼 exit 2 並在 stderr 輸出原因，Codex 會直接硬性攔截該指令並把原因回饋給模型修正！
  • PostToolUse：代理修改檔案或執行工具後觸發，最適合自動執行 Prettier、ESLint、Ruff 等程式碼格式化與靜態檢查。
  • Stop：代理準備結束當前輪次前觸發，可用於確認所有必跑測試皆已執行。
.codex/hooks.json 實戰設定範例（攔截危險指令 + 改檔後自動排版）
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "node ./scripts/verify-safe-bash.mjs",
            "timeout": 10,
            "statusMessage": "正在檢查終端機指令安全性..."
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write .",
            "timeout": 30,
            "statusMessage": "正在自動執行 Prettier 排版..."
          }
        ]
      }
    ]
  }
}

2. 模型上下文協定（MCP）：在 config.toml 或 CLI 連接開發工具

除了從桌面版外掛目錄安裝外，開發者也可透過 CLI 指令 codex mcp add、codex mcp login、codex mcp list，或直接在 config.toml 的 [mcp_servers.<name>] 掛載本機（stdio）或遠端（streamable_http）MCP 伺服器（對話中可隨時輸入 /mcp 查看狀態與啟停）：

config.toml 中的 MCP 伺服器設定範例
# 1. 本機 stdio MCP 伺服器範例（如 Playwright 瀏覽器自動化測試）
[mcp_servers.playwright]
command = "npx"
args = ["-y", "@playwright/mcp@latest"]

# 2. 遠端 Streamable HTTP MCP 伺服器範例（使用 OAuth 驗證，不硬編碼 Token）
[mcp_servers.linear]
url = "https://mcp.linear.app/mcp"
auth = "oauth"

3. 子代理（Subagents / Multi-agent，介面分頁譯為「子智慧體」）：平行拆解大型任務、保護主對話 Context

當主對話需要同時調查十幾個檔案、對比多份文件或執行耗時測試時，若全部在主對話裡進行，工具輸出很快就會塞滿上下文視窗。開啟 Multi-agent（子代理） 功能後，主代理可以派發多個擁有獨立上下文與獨立沙盒權限的子代理平行處理，最後只把精煉結論回傳給主對話（可在對話輸入 /subagents，或從右側「執行摘要 → 子代理」與「子智慧體」分頁查看執行中與已完成的子代理狀態）：

啟用子代理與自訂唯讀研究員角色（.codex/agents/researcher.toml）
# Step 1：於 ~/.codex/config.toml 或 .codex/config.toml 啟用多代理功能
[features]
multi_agent = true

# Step 2：新增 .codex/agents/researcher.toml 定義專屬唯讀子代理角色
name = "researcher"
description = "專門負責跨目錄搜尋、閱讀大型程式碼庫與整理架構摘要的唯讀研究子代理"
model = "gpt-6-luna"
model_reasoning_effort = "medium"
sandbox_mode = "read-only"
developer_instructions = """
你只負責唯讀檢索與結構化整理，絕不修改任何檔案。
回報時請列出確切檔案路徑、行號與關鍵結論，保持精簡以節省主代理上下文。
"""

電腦操控（Computer use）與五大瀏覽器擴充功能

當任務需要操作你電腦中的桌面軟體或外部瀏覽器時，先確認帳號所在地區支援，並到「設定 →（整合）→ Computer use」檢查「控制」與「一律允許的應用」設定。請記住：GUI 應用程式核准與終端機檔案／命令沙盒是兩道獨立的權限邊界：

1. 連接外部瀏覽器與並排側邊欄對話（Side-by-side chat）

官方瀏覽器擴充功能支援五大 Chromium 核心瀏覽器：Google Chrome、Microsoft Edge、Brave、Opera 與 Vivaldi。安裝擴充功能後，除了能在桌面版聊天輸入 @Chrome 或 @Edge 指定已開啟的分頁做讀取、研究、摘要多個分頁或填表外，還支援在瀏覽器視窗內直接開啟 並排側邊欄對話（Side-by-side chat，支援 Chrome、Edge、Brave、Vivaldi），在不離開當前網頁、也不搶奪你滑鼠焦點的情況下邊看網頁邊協作。

內建瀏覽器（@Browser）與你日常使用的個人瀏覽器（如 @Edge）是不同入口，Cookie 登入狀態與存取權限也各自獨立；每次操作前請先確認指定的是哪一個分頁、登入身分以及預計執行的動作。

可以這樣說
使用 @Edge 中我指定的這個分頁，讀取頁面並整理重點摘要。只做讀取，不要送出表單，也不要修改網頁裡的資料。
檔案上傳與跨網站權限檢查

如果網站要求上傳本機檔案，或代理準備跨網站跳轉，請先核對檔案內容、目標網域及擴充功能權限，再決定是否允許。

2. 桌面應用程式操控與安全隔離建議（Windows / macOS）

電腦操控功能可以看見並操作你允許的桌面軟體介面。你可以在對話框輸入 @Computer 或 @應用程式名稱 指定目標軟體：

  • Windows 操作特性：原生軟體操控會直接使用目前的桌面並移動真實滑鼠游標；執行期間請保持目標軟體可見且螢幕未鎖定，不要同時搶著移動滑鼠。
  • macOS 系統權限要求：若在 Mac 上使用，需先至「系統設定 → 隱私權與安全性」手動授權桌面版應用程式「螢幕錄製（Screen Recording）」與「輔助使用（Accessibility）」兩項權限。
  • 安全最佳實踐（最小權限與虛擬機器隔離）：由於 GUI 操控直接模擬人類點擊軟體介面（不受終端機檔案沙盒約束），只應開啟本次任務必要的單一軟體，處理敏感操作時請全程在旁監看；若需執行高風險或長時間無人看管的桌面自動化測試，官方建議在獨立的 Windows 虛擬機器（VM）或隔離環境中運行。任務結束後，可隨時到「設定 → Computer use」檢查「一律允許的應用」清單，或直接關閉「任何應用程式」總開關。

語音對話（Voice）、聽寫與桌面寵物（Pets）

輸入框右下角同時提供「聽寫（Dictation，麥克風圖示，預設快捷鍵 Ctrl + Space）」與「語音對話（Voice，橘色音波圖示）」兩種語音入口：如「設定 → 聲音」所示，按住 Ctrl + Space 即可聽寫，或連按兩下啟用免持模式，把口述內容轉成輸入框文字草稿，讓你檢查專有名詞與路徑無誤後再送出；語音對話則是直接開啟即時雙向通話與任務互動。

  • ChatGPT Voice 即時語音調度：在既有任務中點擊語音圖示，即可直接用口語討論進度、隨時打斷或即時引導，甚至用說的跨任務調度（例如：「幫我切換到正在跑測試的那個專案聊天」）。
  • 桌面寵物（Pets，在對話框輸入 /pet 或至「設定 → Mini 與寵物」）：讓虛擬寵物（如 Codey）或極簡控制列（Mini）懸浮在桌面最上層（亦可從左下角帳號選單點選「顯示寵物 Alt+Win+P」）。即使主視窗收在背景，也能從寵物狀態（Running 執行中、Needs input 等待核准、Ready 已完成未讀、Blocked 發生錯誤）一眼掌握背景任務，並隨時點擊麥克風或輸入框快速發話。
外接硬體選購說明Codex Micro 實體硬體鍵盤（非軟體訂閱內附功能）

官方文件提到的 Codex Micro 為 Work Louder 推出的獨立實體外接控制器（具備 6 顆多色發光 Agent Keys 與旋鈕，可一鍵切換 6 個平行對話），屬於需要額外購買的硬體配件，一般 Free / Plus 使用者直接使用軟體內建的桌面寵物功能（輸入 /pet）即可獲得完整懸浮監看體驗。
