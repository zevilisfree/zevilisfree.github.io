生成圖片、多圖輸入與局部標註修正

可以直接在聊天中描述想要什麼圖片，也可以先上傳參考圖。尺寸、用途、風格以及必須保留的內容，儘量一次說清楚。

圖片輸入（Image input）與圖片生成（Image generation）是兩項不同能力：任何方案都可提供圖片或設計稿供 Codex 分析；而在 Codex 內生成或編輯圖片則依方案可用性與配額而定（官方定價頁目前指出 Free 與 Go 方案不提供 Codex 內建圖片生成）。

  • 桌面版、IDE 與 CLI 附加圖片：在桌面版或 IDE 擴充功能中，直接點擊附件入口，或拖曳圖片至輸入框時按住 Shift 讓圖片加入聊天上下文；在 Codex CLI 則可使用 -i, --image <path> 附加單張或多張圖片（例如 codex -i mockup.png -i error.png "比對設計稿修復畫面"，非互動模式 codex exec -i 同樣支援）。官方圖片輸入說明。
  • 多張參考圖編號法：同時上傳多張圖時，可在提示詞明確指定每張圖的角色，例如：「圖 1 是要修改的產品首頁截圖，圖 2 是品牌配色與卡片陰影參考，請保留圖 1 的版面結構並套用圖 2 的視覺風格」。

圖片產生後，點擊圖片開啟「圖像」檢視器。需要針對局部區域修改時，不必整張重抽：

  1. 點擊生成的圖片進入「圖像」檢視模式（左上角可切換圖像版本，右上角可調整縮放比例、下載或於外部程式開啟）。
  2. 使用圖片下方懸浮工具列的「標註」（手繪塗抹）或「留言」（局部框選加號）工具，圈選或點擊需要修改的位置（工具列亦直接提供「移除背景」、「擦除」與「調整大小」快捷功能）。
  3. 寫清楚「要改成什麼」以及「哪些部分不要動」。
  4. 檢查附上的圖片與標註內容，再依目前介面的提示送出修改要求。

視窗快照（Appshots）：一鍵擷取畫面與捲動區外的文字層

當你想讓 ChatGPT Work 或 Codex 查看另一個軟體的報錯視窗、終端機輸出、設定面板、Figma 設計稿或文件時，不必手動截圖存檔再上傳！你可以從輸入框左下角「+」選單點選「附加〈目前開啟的應用程式名稱〉」，或直接按下「設定 → Appshots」中的快速鍵（預設為 Alt + Alt，即同時按下鍵盤左右兩個 Alt 鍵），一鍵拍下最上層視窗的 Appshot（應用程式視窗快照）：

  • 同時擷取像素畫面與視窗可讀文字層：Appshot 不僅會拍下目前視窗的可見像素畫面，若該應用程式支援無障礙文字讀取，還會一併提取視窗內（包含部分捲動到螢幕外）的可讀取文字層，讓你省去手動複製貼上長篇錯誤 Log 的麻煩。部分純圖形介面軟體只能提供像素截圖，送出前可先點擊附件確認內容。
  • 設定快速鍵、Appshot 目的地與播放音效：在「設定 → Appshots」中，可自訂「快速鍵」（預設：同時按下兩個 Alt 鍵）、「Appshot 目的地」（預設為「自動」，可選擇使用快速鍵時要送往目前對話或新對話）與「播放音效」。發送前請確認目標視窗沒有顯示未遮蔽的密碼或私密對話。

內建瀏覽器註解（Adjust）、開發者模式（CDP）與 Site Tools（WebMCP）

當前端網頁或本機開發伺服器（如 localhost:3000）在右側內建瀏覽器（@Browser）中開啟後，你可以直接在頁面上圈選元素、即時拉動樣式預覽，甚至授權讀取底層 DevTools 資訊，完全不必再用長篇文字苦苦描述「左上角第二顆按鈕往右移一點」（在「設定 → 瀏覽器」中，建議將「本機 URL 開啟目標」設為 ChatGPT，並確認「註解螢幕截圖」設為「一律包含」以輔助定位）。

  1. 開啟頁面並進入註解模式（Annotate）

    點擊預覽網址在右側開啟內建瀏覽器，點選瀏覽器工具列的註解（Annotate）按鈕。若要檢查特定互動狀態（如展開下拉選單或彈跳視窗），請先把網頁操作到該狀態再進入註解。

  2. 選取 DOM 元素或拖曳框選區域

    直接點擊目標文字、按鈕或卡片元素，或拖曳選取一塊區域。出現選取外框後，確認鎖定範圍精準。

  3. 使用調整（Adjust）即時微調 CSS 樣式並轉寫回原始碼

    點開輸入框旁的「調整（Adjust）」面板，直接在畫面上拉動調整字型大小、字重、內外間距（Padding / Margin）、顏色與圓角並即時預覽效果。調整到滿意後儲存註解送出，Codex 就會直接把你調好的視覺數值精準寫回專案的 CSS 或 Tailwind 原始碼！

💡 前端除錯進階雙武：開發者模式（CDP）與 Site Tools（WebMCP）
  • 開發者模式（Developer Mode / Full CDP Access）：遇到「按下按鈕沒反應」或 API 請求失敗時，可至「設定 → 瀏覽器（Browser）」開啟 Developer mode（Enable full CDP access）。啟用 Chrome DevTools Protocol（CDP）後，Codex 可在你的授權下直接讀取瀏覽器的 Console 報錯堆疊、Network API 請求與回應 Payload、DOM 結構及效能數據，一次定位前後端根因（開啟前請確認分頁未包含敏感個人登入憑證）。
  • Site Tools（WebMCP 網頁原生工具註冊）：根據 官方瀏覽器文件，支援 WebMCP 標準（document.modelContext.registerTool）的現代網頁應用程式，可直接向內建瀏覽器註冊結構化操作工具（並附帶 readOnlyHint 唯讀、untrustedContentHint 不可信內容、consequentialHint 重要副作用等安全標記）。你可從瀏覽器網址列旁的指示器檢視並授權，讓代理直接呼叫網站原生功能，而不必依賴螢幕座標盲點點擊。

互動視覺化（@Visualize 與 Space /visualize）

當純文字或靜態圖片不足以表達複雜公式、演算法狀態或商業預測模型時，你可以在對話框輸入 @Visualize（從外掛選單選取 Visualize），請 ChatGPT 或 Codex 直接在對話中生成可拖曳滑桿、可切換視角與即時試算參數的互動式圖表、架構模擬器或資料儀表板。

若你正在團隊協作的 ChatGPT Space（Pages 共編頁面，詳見第 11 章） 撰寫規格書或分析報告，更可以直接在頁面內輸入斜線指令 /visualize + 描述（例如：/visualize 根據上方表格數據製作可調整轉換率與客單價的營收預測試算器），將活的互動式小工具直接嵌入文件中供團隊成員操作驗證。

ChatGPT Work 母版套用、檔案預覽器與四大檔案局部標註（Annotations）

桌面版可在右側預覽支援的文件、試算表、簡報與 PDF，並對部分格式加上局部標註；Web 版的預覽與修訂方式可能不同，應開啟或下載產物逐頁檢查。Codex CLI 會在本機路徑產出檔案，沒有同樣的視覺預覽介面。

若你想在 ChatGPT Work 做出可審閱的商務檔案，可參考官方 Work with files 流程：

  1. 拒絕每次從零排版——上傳母版與範本（Master Templates & @Template-Creator）：

    不要只用一句話叫 AI「幫我做一份好看的簡報」。實戰上請先附上公司標準配色的 .pptx 簡報母版、固定欄位格式的 .xlsx 財務模型，或標準合約排版的 .docx 範本（也可呼叫 @Template-Creator 將既有檔案封裝為可重複使用的標準母版），要求 Work：「嚴格沿用這份簡報母版的版面配置、字型與色票，將本週專案數據填入對應頁次」。

  2. 用右側預覽器的「局部圈選標註（Annotations）」取代整份重做：

    在支援標註的預覽器中，圈選目標並描述想改的內容與應保留的範圍；修訂後仍須檢查整份檔案，確認其他段落沒有意外變更：

    • Word 文件與 PDF（Documents / PDF）：反白或圈選報告中的某一段落，留言「核對這段數據的原始出處並改寫為條列式；其他章節請保持原樣」。完成後仍須檢查整份文件與版面。
    • PowerPoint 簡報（Presentations）：圈選第 4 張投影片上的某個圖表或文字框，留言「將這張圓餅圖改為水平長條圖並放大數據標籤」，不會影響其他投影片版面。
    • Excel 試算表（Spreadsheets）：圈選特定儲存格範圍或樞紐分析表，要求檢查公式參照錯誤、補上條件式格式或依該區間新增視覺化圖表。
    • HTML 網頁與 LaTeX（.tex）雙模式檢視：預覽器對 .html 支援「即時互動渲染畫面」與「原始碼（Source）」一鍵切換；對專業論文與技術文件常用的 LaTeX（.tex） 更支援「左側修改原始碼、右側即時編譯 PDF 預覽」的雙向檢視！

驗收檔案時，請依序確認三件事：① 檔案確實已儲存至預期路徑且檔名正確；② 在預覽器或本機軟體開啟後版面與公式正常，而非只看聊天文字說「已完成」；③ 點擊右側 Review 面板核對實際檔案 Diff。網頁只在本機執行時，預覽網址為 localhost 或 127.0.0.1，能在自己電腦開啟不代表已公開發布（若需託管並分享網站，請使用第 11 章介紹的 ChatGPT Sites）。

修改後再看一遍：視覺與響應式驗收清單

在預覽器拉動樣式（Adjust）或留下標註（Annotations）後，等代理執行完畢，請重新整理預覽畫面並逐項檢查：

  • 圖片與簡報：檢查文字拼寫、數據標籤、元素數量與比例，確認有沒有連帶改動到原本已經滿意的區域。
  • 網頁與前端元件：檢查桌面寬度與手機窄螢幕（Responsive）版面是否完整、深淺色主題切換是否正常，並在開啟 CDP 時確認 Console 為零報錯。
  • 結果不符預期時：保留上一版結果（或透過 Git Review 面板 Revert 單一區塊），在預覽器重新精準框選差異處，再繼續微調。
