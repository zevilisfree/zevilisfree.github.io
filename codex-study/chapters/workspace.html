安裝、登入與建立第一個專案

從 Windows 檔案總管建立資料夾，登入 Codex、認識主畫面並調整外觀；開發工具可按需要安裝。

02
Windows 桌面版與跨端點 依 2026-10-16 文件查核 點擊截圖可放大

Codex 安裝與建議工具鏈

官網介紹：openai.com/codex ｜ Microsoft Store（微軟商店）：下載 Windows 版

新手先從上方 Microsoft Store 安裝桌面版，登入後即可繼續到「建立工作空間」。熟悉終端機、確實需要命令列工具時，再使用以下選用指令：

選用：winget、Codex CLI 與開發工具
終端機快速安裝指令
# 使用 winget 安裝 ChatGPT / Codex Windows 桌面版
winget install --id 9PLM9XGG6VKS -s msstore

# （選用）安裝 Codex CLI 終端機版並登入同一個 ChatGPT 帳號
npm install -g @openai/codex
codex login

若任務需要版本管理、程式執行或建置，再選擇安裝下列工具；初次使用桌面版不必先全部裝好：

  • Git（winget install --id Git.Git）：提供右側差異檢視（Review）面板、版本還原與 Git Worktree 隔離功能。
  • Node.js 與 Python（OpenJS.NodeJS.LTS / Python.Python.3.14）：讓代理能快速執行資料清理、自動化腳本與前端預覽伺服器。
  • .NET SDK 與 GitHub CLI（Microsoft.DotNet.SDK.10 / GitHub.cli）：建置原生 Windows 應用，並透過 gh auth login 啟用內建 GitHub PR 與 Issue 整合。
遇到 PowerShell 無法載入腳本（Execution Policy）錯誤？

若在 Windows 首次使用 Node.js / npm 或執行 Codex 產生的 .ps1 腳本時出現 running scripts is disabled on this system，先確認要執行的腳本及來源；若只是使用 npm，可在 PowerShell 嘗試 npm.cmd，或改用命令提示字元。若組織政策限制腳本，請依管理員規範處理，不要為了安裝教學直接放寬整台電腦的執行原則。

Codex 基本使用

首次啟動請使用 ChatGPT 帳號登入，免費帳號（Free）的額度即可體驗本機資料夾讀寫與基礎功能；雲端與遠端能力依帳號、工作區與推出進度而異，請以目前介面及官方方案頁核對。

調整外觀與閱讀偏好

從主選單開啟「設定 → 外觀」，依需求調整主題與顯示方式。不同版本的選項可能不同，先看預覽，再選擇適合自己螢幕的設定。

建立工作空間

本機專案對應電腦裡的資料夾。資料夾用來儲存實際檔案，專案底下的聊天則負責處理不同任務。

  1. 先建立一個資料夾

    在檔案總管中選擇有足夠空間的位置，新增專門的工作資料夾。可以放在 D 槽，不必全部放在 C 槽。既有的資料夾也可以直接使用。

  2. 把資料夾加入為專案

    在 Codex 左側「專案」旁點擊新增入口，選擇資料夾；也可以直接把資料夾拖曳到專案區。核對路徑後，填寫好辨識的專案名稱。

  3. 在專案裡開始聊天

    點進剛建立的專案，再點擊新增聊天。發送前先看輸入框上方的專案與環境資訊，確認是剛才選定的資料夾與本機環境。

可以先做一次唯讀檢查：

可以這樣說
告訴我目前的工作目錄，以及目錄裡有哪些檔案。先不要建立、移動或修改檔案。

回答中的路徑應與檔案總管裡一致。如果路徑不對，請先重新選擇目錄。

第一個小任務：建立並檢查練習檔

確認目錄正確後，在同一個聊天請 Codex 建立一個純文字檔。這個練習不需要 Git、Node.js 或 Python。

下方訊息包含目標（Goal：建立檔案）、背景（Context：目前練習資料夾）、限制（Constraints：只做這件事）與完成判準（Done when：回報路徑與內容）。較複雜的工作也能依這四項組織要求；完整寫法見第 8 章任務提示詞。

可以這樣說
只在目前的練習資料夾建立 welcome.md，寫下三行：標題「我的第一個 Codex 任務」、今天想學的功能、下一步要檢查的結果。完成後告訴我檔案的完整路徑與實際內容。

到 Windows 檔案總管開啟剛才的資料夾，確認 welcome.md 存在、內容符合要求，且沒有多出不需要的檔案。若要改一行文字，可在同一聊天明確指出要改哪一行；改完再開啟檔案核對。若專案已啟用 Git，右側差異檢視（Review）還能顯示變更，讓你逐項確認；沒有 Git 時直接看檔案即可。官方程式碼審查說明也提醒，差異檢視會反映整個 Git 專案的變更，未必全由 Codex 產生。

提示沒有權限建立目錄？

如果目標的上層資料夾不存在，請先在檔案總管裡手動建立，再將它加入專案中。不要為了建立一個資料夾，就開放整個磁碟的存取權限。

單一專案連結多個資料夾與 WSL2 支援

當你的工作分散在不同位置（例如「前端網站資料夾」與「後端 API 資料夾」，或「主程式」與「共同規範文件庫」）時，不需要拆成兩個專案（此為桌面版內建功能，Free 與 Plus 皆可使用）：

  1. 開啟專案選單並選擇「編輯專案（Edit project）」，點擊「新增資料夾（Add folder）」即可在同一個專案掛載多個資料夾。
  2. 將滑鼠移到最常使用的資料夾上，選擇「設為主要（Make primary）」。新聊天預設在主要資料夾啟動；Codex 從這裡自動尋找 AGENTS.md、技能（Skill）與 config.toml。次要資料夾可供搜尋與讀寫，但不會自動從其中發現這些設定檔。
  3. 若你的專案放在 WSL2（Windows Subsystem for Linux 2） 中，選取資料夾路徑時輸入 \\wsl$\ 即可選取 Linux 發行版中的目錄；也可在「設定」中將代理執行環境與內建終端機（PowerShell / Command Prompt / Git Bash / WSL）切換為 WSL2。

專案歸屬、釘選與活動中心

一個專案可以有多則聊天對話。討論同一批檔案的任務請放在同一個專案裡；無關的工作則另外建立專案，之後會更好找。

如果既有的聊天放錯位置，對著聊天按右鍵，找到「專案」，選擇目標專案。移動之後，記得再次核對工作目錄；變更聊天分類不等於把檔案也一起搬過去。

  • 釘選（Pin）：對常用專案或核心聊天點擊右鍵選單的「釘選」（或輸入 /pin）固定至側邊欄頂部。釘選僅固定顯示位置，不會自動把該聊天的內容注入其他對話。
  • 封存（Archive）：任務完成後點擊選單中的「封存」（或輸入 /archive）封存聊天，保持側邊欄清爽；日後可隨時從「設定 → 已封存的聊天」還原。
  • 活動中心（Activity View）：點擊側邊欄的「鈴鐺」圖示，可集中檢視所有未讀、背景執行中或正等待你核准的聊天，也能一鍵清除所有未讀標記。
