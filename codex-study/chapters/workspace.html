桌面版與 Codex CLI 安裝、實戰指令與建議工具鏈

官網介紹：openai.com/codex ｜ Microsoft Store（微軟商店）：下載 Windows 版

初學者建議先從上方 Microsoft Store 安裝 Windows 桌面版，登入後即可直接體驗 ChatGPT、Work 與 Codex。若你習慣在終端機（PowerShell / WSL2）開發，或需要將 Codex 串接進自動化腳本與 CI/CD 管線，可一併安裝 Codex CLI（CLI 與桌面版共用同一個 ~/.codex/config.toml 設定檔、技能與記憶庫）：

桌面版與 Codex CLI 安裝指令
# 1. 使用 winget 安裝 ChatGPT / Codex Windows 桌面版
winget install --id 9PLM9XGG6VKS -s msstore

# 2. 若已安裝 npm，可用 npm 安裝 Codex CLI；Node.js 版本請依目前官方安裝頁核對
npm install -g @openai/codex
codex login

# （選用）在 WSL2 / Linux / macOS 亦可使用官方獨立安裝腳本：
# curl -fsSL https://chatgpt.com/codex/install.sh | sh
# （選用）在無瀏覽器的遠端主機（Headless）登入：
# codex login --device-auth

進階選讀：Codex CLI 互動模式、非互動管線（exec）與常用旗標

Codex CLI 不只是把聊天搬進終端機，它還支援非互動模式（codex exec，簡寫 codex e）——執行過程的思考與工具日誌會輸出至 stderr，而最終答案則乾淨地輸出至 stdout，極適合搭配管道（Pipe）或寫入自動化腳本：

Codex CLI 核心實戰命令範例
# 啟動互動式 TUI（可直接帶入初始任務，或用 -i 附上一至多張錯誤截圖）
codex "先盤點目前目錄架構，不要修改檔案"
codex -i ui-bug.png "比對截圖修正導覽列跑版問題"

# 從終端機當前目錄直接喚起桌面版 App 對應專案
codex app

# 非互動模式（codex exec / codex e）：結合 git diff 自動產生 Commit 訊息或結構化 JSON 報告
git diff --staged | codex exec "根據差異產出符合 Conventional Commits 的繁體中文提交訊息"
codex exec -s workspace-write -m gpt-6.1-sol "執行單元測試並修復失敗項目"
codex exec "檢查依賴安全性" --output-schema ./schema.json -o ./audit-report.json

# 接續歷史對話（Session Resume）與套用雲端任務修補（Apply）
codex resume                  # 開啟互動清單挑選過去的工作階段
codex resume --last           # 直接接續上一場對話
codex exec resume --last "繼續修完剩下的型別錯誤"
codex apply <TASK_ID>         # 將 Codex Cloud 雲端任務產出的最新 Diff 套用回本機工作樹
  • 常用 CLI 啟動旗標（Flags）：-m, --model <model>（指定模型如 gpt-6.1-sol 或 gpt-6-luna）、-s, --sandbox <mode>（指定沙盒模式：read-only、workspace-write、danger-full-access）、-a, --ask-for-approval <policy>（指定核准政策：on-request 或 never）、-C, --cd <path>（指定工作目錄）、--add-dir <path>（額外授權可寫入的資料夾）、-c, --config <key=value>（臨時覆寫 config.toml 參數）。
  • CLI TUI 鍵盤技巧：在終端機互動介面中，輸入 @ 可模糊搜尋並附加專案檔案；輸入 ! 可直接執行本機 Shell 指令；執行中按 Tab 可排入下一輪跟進提示詞（Queue）；按 Ctrl + L 可清除畫面雜訊並保留對話上下文。
選用：安裝 Git、Node.js、Python 與 GitHub CLI 等開發工具鏈

若任務需要版本管理、程式執行或建置，再按需安裝下列工具；初次使用桌面版處理一般檔案不必先全部裝齊：

  • Git（winget install --id Git.Git）：啟用右側差異檢視（Review）面板、版本還原與 Git Worktree 平行隔離功能。
  • Node.js 與 Python（winget install --id OpenJS.NodeJS.LTS ／ winget install --id Python.Python.3.14）：讓代理能執行資料清理、自動化腳本、前端預覽伺服器與 MCP 工具。
  • .NET SDK 與 GitHub CLI（winget install --id Microsoft.DotNet.SDK.10 ／ winget install --id GitHub.cli）：建置原生 Windows 應用，並透過 gh auth login 啟用內建 GitHub PR 與 Issue 整合。
遇到 PowerShell 無法載入腳本（Execution Policy）錯誤？

若在 Windows 首次使用 Node.js / npm 或執行 Codex 產生的 .ps1 腳本時出現 running scripts is disabled on this system，先確認要執行的腳本及來源；若只是使用 npm，可在 PowerShell 嘗試 npm.cmd，或改用命令提示字元（cmd）。若組織政策限制腳本，請依管理員規範處理，不要為了安裝教學直接放寬整台電腦的執行原則。

登入與認識桌面版三欄主畫面

首次啟動請使用 ChatGPT 帳號登入。免費帳號（Free）與 Go 方案即可體驗本機資料夾讀寫與基礎功能；Plus 與 Pro 方案則進一步解鎖更多模型配額、雲端任務（Codex Cloud）與手機遠端連線（Remote）。

調整外觀與閱讀偏好

從主選單開啟「設定 → 外觀」，依需求調整深淺色主題、色彩與字型顯示方式。不同版本的選項可能略有差異，先看預覽，再選擇適合自己螢幕的設定。

建立專案工作空間、專案專屬指令與隔離記憶

桌面版的 Projects 檢視可包含 ChatGPT 專案與連接電腦資料夾的本機專案。兩者都能整理相關工作，但資料來源與權限不同：ChatGPT 專案的上傳檔案不等於 Codex CLI 的工作目錄，本機專案也不表示雲端聊天自動讀到電腦資料夾。官方：Projects and chats

  1. 先建立或挑選一個專屬資料夾

    在 Windows 檔案總管中選擇有足夠空間的位置，新增專門的工作資料夾（可放在 D 槽等非系統磁碟，或直接使用既有專案資料夾）。請避免直接將整個 C:\ 或包含大量私密憑證的「桌面／下載」根目錄設為工作區。

  2. 把資料夾加入為專案，並設定專案指令與記憶範圍

    點擊輸入框上方的「選擇專案 → + 新專案」（或在左側「專案」旁新增、將資料夾拖曳到專案區）。建立或編輯專案時，除了確認資料夾路徑外，還可設定兩項關鍵功能：

    • 專案專屬指令（Project Instructions）：定義只在這個專案內生效的背景說明、角色設定、輸出格式（例如「本專案所有財報分析皆以新台幣千元為單位」），在 Chat 與 Work 模式下同樣會自動套用。
    • 專案記憶設定：先檢查目前專案可用的記憶選項及分享對象。記憶設定有助於管理對話脈絡，但不能取代檔案權限、來源連線、成員存取和資料控制；敏感業務先以非敏感測試資料確認實際行為。

  3. 在專案裡開始新對話（支援跨模式接力）

    點進剛建立的專案並按左上角「新對話」。發送前先看輸入框上方的專案與環境標示（如「專案名稱」與「這台電腦」），確認是剛才選定的資料夾與本機環境。你可以在同一個專案下用 Chat 討論、用 Work 產出報告，或切到 Codex 寫程式。

初次進入新專案時，可以先做一次唯讀檢查：

可以這樣說
告訴我目前的工作目錄，以及目錄裡有哪些檔案。先不要建立、移動或修改檔案。

回答中的路徑應與檔案總管裡完全一致。如果路徑不對，請先重新選擇目錄。

第一個小任務：建立並檢查練習檔

確認目錄正確後，在同一個聊天請 Codex 建立一個純文字檔。這個練習不需要 Git、Node.js 或 Python。

下方訊息包含目標（Goal：建立檔案）、背景（Context：目前練習資料夾）、限制（Constraints：只做這件事）與完成判準（Done when：回報路徑與內容）。較複雜的工作也能依這四項組織要求；完整寫法見第 10 章任務提示詞。

可以這樣說
只在目前的練習資料夾建立 welcome.md，寫下三行：標題「我的第一個 Codex 任務」、今天想學的功能、下一步要檢查的結果。完成後告訴我檔案的完整路徑與實際內容。

到 Windows 檔案總管開啟剛才的資料夾，確認 welcome.md 存在、內容符合要求，且沒有多出不需要的檔案。若要改一行文字，可在同一聊天明確指出要改哪一行；改完再開啟檔案核對。若專案已啟用 Git，右側差異檢視（Review）還能顯示變更，讓你逐項確認；沒有 Git 時直接看檔案即可。官方程式碼審查說明也提醒，差異檢視會反映整個 Git 專案的變更，未必全由 Codex 產生。

提示沒有權限建立目錄？

如果目標的上層資料夾不存在，請先在檔案總管裡手動建立，再將它加入專案中。不要為了建立一個資料夾，就開放整個磁碟的存取權限。

單一專案連結多個資料夾、Primary Folder 與 WSL2 支援

當你的工作分散在不同位置（例如「前端網站儲存庫」與「後端 API 儲存庫」，或「主程式資料夾」與「產品規格／母版文件資料夾」）時，不需要拆成兩個專案（此為桌面版內建功能，Free 與 Plus 皆可使用）：

  1. 開啟專案選單並選擇「編輯專案（Edit project）」，點擊「新增資料夾（Add folder）」即可在同一個專案掛載多個本機資料夾。
  2. 將滑鼠移到最常使用的主力資料夾上，選擇「設為主要（Make primary）」。新聊天預設會在主要資料夾（Primary folder）啟動；Codex 會以主要資料夾為基準自動探索並載入 AGENTS.md、技能（.agents/skills/）與 .codex/config.toml。其他附屬資料夾同樣可供跨目錄搜尋、讀取與編輯，讓你在同一個對話內同時參考規格文件並修改前後端程式碼。
  3. WSL2（Windows Subsystem for Linux 2）整合與環境一致性建議：若你的專案放在 WSL2 中，選取資料夾路徑時輸入 \\wsl$\（或 \\wsl.localhost\）即可選取 Linux 發行版中的目錄；也可在「設定 → 一般 → 整合的終端 Shell」將內建終端機（PowerShell / Command Prompt / Git Bash / WSL）切換為 WSL2。實戰建議：同一個專案的多個資料夾請盡量統一放在原生 Windows 路徑（如 C:\、D:\）或統一放在 WSL2 檔案系統內，避免跨 Windows 與 Linux 檔案系統混掛導致路徑格式（\ vs. /）、符號連結或套件建置效能受影響。

專案歸屬、釘選、活動檢視與執行摘要

一個專案可以包含多則聊天對話。相關工作放在同一專案有助整理，但不同端點是否可使用相同檔案、指示或記憶，仍須依專案類型與當前執行環境檢查；無關工作則另外建立專案。

如果既有的聊天放錯位置，對著聊天按右鍵，找到「專案」，選擇目標專案。移動之後，記得再次核對工作目錄（或在對話中輸入 /pwd 檢查、用 /cd 切換）；變更聊天分類不等於把硬碟裡的檔案也一起搬過去。

  • 釘選（Pin）：對常用專案或核心聊天點擊右鍵選單的「釘選」（或輸入 /pin）固定至側邊欄頂部。釘選僅固定顯示位置，不會自動把該聊天的內容注入其他對話。
  • 封存（Archive）：任務完成後點擊選單中的「封存」（或輸入 /archive）封存聊天，保持側邊欄清爽；日後可隨時從「設定 → 已封存的對話」（或「設定 → 資料控制 → 已封存的對話」）還原。
  • 活動檢視（Activity View，快捷鍵 Ctrl + Alt + U）：點擊側邊欄上方的「鈴鐺」圖示，可依「優先順序」、「今天」、「昨天」集中檢視所有未讀、背景執行中或正等待你核准的聊天，也能一鍵清除所有未讀標記。
  • 聊天執行摘要（Run Summary）：聊天右側的執行摘要面板會即時彙整該任務的「方案」（Plan）、「輸出內容」（Outputs）、「子代理」（Subagents，詳見第 9 章）與「來源」（Sources），方便快速盤點進度；但摘要不等於最終驗收，完成後仍應開啟實際檔案或 Review 面板核對。
