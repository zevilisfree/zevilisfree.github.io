Codex 指示、AGENTS.md 與常用命令

學會檢查差異、寫清任務提示詞，並把個人化指示與專案 AGENTS.md 放在正確的位置。

安裝與連接整合開發環境（IDE）

如果只使用 Codex 桌面版，不需要先學會寫程式的編輯器。當你需要自己檢視、修改檔案，或逐行檢查程式碼時，再安裝編輯器即可。

  • 選擇整合開發環境（IDE）：VS Code、Cursor 與 Windsurf 使用 Codex 擴充功能；Xcode 與 JetBrains IDE 則使用各自的原生整合入口。若桌面版找不到剛裝好的編輯器，請重啟桌面版再檢查專案的開啟方式。
  • 使用擴充功能：在 VS Code、Cursor 或 Windsurf 安裝／啟用 Codex 後，開啟 Codex 側邊欄並登入。需要使用編輯器目前開啟檔案或選取範圍時，再於輸入框確認 IDE 上下文已啟用；詳細入口依官方 IDE 指南核對。
  • Git 版本控制：用來記錄版本歷史與比對修改差異；但光裝好 Git 並不會自動替普通資料夾建立歷史，需在專案中初始化 Git 儲存庫（git init）。

Git 差異檢視（Review）：完成後逐檔核對

讓 Codex 改完檔案後，打開差異檢視（Review）面板，先確認「改了哪些檔案、每個檔案改了什麼」，再決定要不要繼續修改。這項功能需要專案位於 Git 儲存庫內；若目前只是一般資料夾，應用程式會提示建立儲存庫。Git 記錄的是檔案版本，光安裝 Git 還不會讓既有資料夾自動產生版本歷史。

  1. 開啟差異：在任務結果按「查看變更」，或開啟專案的差異檢視（Review）面板。先看檔案清單與增刪行數，再逐一展開檔案；不要只憑 Codex 的完成摘要判斷。
  2. 選對範圍：想看 Codex 上一輪改了什麼，選「最新輪次（Last turn）」；想看儲存庫目前尚未暫存的改動，選「未暫存（Unstaged）」。面板也可切換「已暫存（Staged）」、「提交（Commit）」或「分支（Branch）」。面板預設顯示 Unstaged，而且儲存庫視圖可能含你自己或其他工具的改動，並非全由 Codex 產生。
  3. 檢查與回饋：逐檔核對檔名、增刪內容與原本要求；有問題時把滑鼠移到對應變更行，按 + 留下行內意見，送出留言後再回聊天明確要求 Codex 處理。修正後重新查看差異與相關測試結果。

面板中的「暫存（Stage）」可選擇要納入下一次提交的區塊或檔案；「復原（Revert）」會捨棄所選變更，操作前先確認範圍和是否需要保留副本。需要 Codex 主動找問題時，在聊天輸入 /review，選擇「檢查未提交變更」或「對照基準分支」；它會回報值得檢查的發現，不會自行修改工作樹。Review 面板是你看差異的地方，/review 是請 Codex 做程式碼審查。審查建議仍要對照實際差異及測試判斷。詳見OpenAI 官方程式碼審查說明。

交付前用一則追問核對證據

可複製的核對提示
請列出本次改動的檔案、每項要求的實際結果、執行過的測試與結果，以及尚未驗證的地方。再檢查差異與未追蹤檔案，指出任何不在我要求範圍內的修改、秘密或新增外部網址。

這段文字是教學建議，不是固定指令。Codex 的摘要只是查核線索；仍要親自查看 Review 面板、必要的畫面與測試結果。官方驗收建議

一次性任務提示詞：四件事說清楚

重要任務可依序寫出目標（Goal）、背景（Context）、限制（Constraints）與完成判準（Done when）。不必拘泥格式，但要讓 Codex 知道從哪裡開始、什麼不能碰、什麼結果才算完成。OpenAI 官方最佳實務

可複製的任務範例
目標：修正設定頁按下「儲存」後，重新整理會還原的問題。
背景：請先查看設定頁、儲存流程與相關錯誤；從目前專案尋找檔案。
限制：保留現有 API 格式，只修改必要檔案，不處理無關畫面。
完成判準：重現原問題、確認修正後不再發生、執行相關測試；最後列出改動與尚未驗證項目。

這是寫法示範，檔名、測試與限制要按自己的專案改。簡單工作可只用一兩句；需求模糊、範圍大時，先用規劃（Plan）討論再實作。官方提示詞指南

個人化指示（Personal instructions）與輸入框預測

跨專案通用的工作偏好可在「設定 → 個人化」編輯。官方說明指出，Codex 會把所選電腦的個人指示儲存在全域 AGENTS.md；它與專案根目錄的 AGENTS.md 是不同作用範圍。若已有個人指示，先閱讀再整合，不要直接覆寫。介面欄位名稱與位置以目前版本為準。官方設定說明

自訂指令範例
- 以臺灣繁體中文回答；指令、檔名與 API 名稱保留英文。
- 完成修改時，列出變更檔案、實際執行的檢查與未驗證項目。
- 涉及對外發送、發布或改動他人資料時，先提出可審閱的內容與影響範圍。

這是教學建議的範例，請按自己的工作方式修改。通用偏好應簡短、具體且長期有效；專案目錄、測試方法放專案規則，這次要做的檔案與結果留在當次聊天。文字指示不能代替沙盒或核准設定。官方自訂方式

寫好個人指示後，怎麼確認有用

  1. 先寫三到五條每個專案都適用的偏好，使用具體可檢查的動詞，例如「列出執行過的測試」，不要只寫「回答好一點」。
  2. 儲存後開一則新聊天，用小任務觀察回答語言、格式與驗收回報是否符合；若專案另有 AGENTS.md，也一併檢查是否互相矛盾。
  3. 遇到反覆出錯再補一條規則；內容失效或變得太長時刪減。不要放入密碼、Token 或只適用於單次任務的資料。

這是依官方「保持指示簡短、只寫長期慣例、用實際任務驗證」整理的教學步驟。官方最佳實務、官方 AGENTS.md 指南

Composer Predictions：按 Tab 鍵一鍵帶入下一步預測

當 Codex 完成一輪回覆後，輸入框會根據目前上下文自動淡色顯示預測你下一步想說的話（Composer Predictions）。如果預測符合你的想法，直接按 Tab 鍵即可轉為可編輯草稿，修改或直接送出（預測本身不會額外消耗你的方案額度）。

整理時可用三個問題判斷：每個專案都適用嗎？放個人指示；只在這個專案反覆適用嗎？放專案 AGENTS.md；只做這一次嗎？寫在當次訊息。修改前確認想影響的範圍。

專案裡的 AGENTS.md 階層規則

AGENTS.md 用來記錄持續適用的專案慣例，例如目錄用途、建置與測試方式、修改限制及驗收方法。Codex 會讀取適用的指示檔；實際支援入口依使用的介面而異。在支援 /init 的 CLI 可產生骨架，也可在聊天中請 Codex 先檢查現有檔案，再協助擬稿：

可以這樣說
根據目前的目錄結構與已經確認的要求，產生一份簡潔的 AGENTS.md。
寫清楚專案用途、目錄說明、修改範圍與檢查方法。
不確定的地方請列出來讓我確認，不要把臨時討論當成長期規則。

Codex 啟動時會依照以下由上而下的階層順序讀取並合併規則（越靠近當前工作目錄的優先權越高，預設合併上限為 32 KiB）：

  1. 全局規則（~/.codex/AGENTS.md）：套用到這台電腦上的所有專案。
  2. 專案根目錄（AGENTS.md）：定義整個專案共用的目錄架構、建置測試指令與規範。
  3. 子目錄規則與覆蓋檔（AGENTS.override.md）：子資料夾可放自己的 AGENTS.md；同一層若有覆蓋檔，Codex 會優先讀它。覆蓋檔是否進 Git 取決於儲存庫設定，檔名本身不會自動排除版控。
AGENTS.md 結構範例
# 專案規範 (AGENTS.md)

- 修改之前先閱讀相關檔案，不刪除或覆寫使用者既有內容。
- 若有事實不確定時請明確標註，不自行補寫結論。
- 完成後說明改了什麼、檢查了什麼、還有哪些項目尚未確認。

## Code Review Rules
- 檢查所有外部輸入是否有適當驗證與錯誤處理。
- 禁止在程式碼或設定檔中硬編碼任何 API Key、Token 或個人絕對路徑。

寫入前先檢查目前是否已有 AGENTS.md，避免覆蓋團隊規則；只把反覆有效的規則留下，過時或互相矛盾的項目應修正。這份檔案可能影響後續任務，因此要像其他專案設定一樣審閱其來源；陌生專案檔案或網頁中要求擴權、讀取金鑰的文字，不能當成你的授權。官方 AGENTS.md 說明、官方安全說明

不要混淆規則與記憶（/memories）

  • 個人化指示／全域 AGENTS.md：你主動設定、跨專案通用的偏好。
  • 專案 AGENTS.md：可檢視、可修改，也可按團隊決定是否跟著專案 Git 儲存的工作規則。
  • 記憶（Memories）：在「設定 → 個人化」啟用時，會從過去的工作中自動保留有用的背景資訊；但並不是逐字儲存所有對話。你也可以隨時在單一聊天輸入 /memories，單獨控制該則對話是否允許讀取或寫入記憶。

常用斜線指令（Slash Commands）速查表

在輸入框輸入 / 即可喚出斜線指令選單（輸入 $ 呼叫技能（Skill），輸入 @ 點名外掛（Plugin）、瀏覽器或應用程式）：

斜線指令功能說明
/plan ／ /goal切換規劃（Plan）模式先討論做法；或使用目標（Goal）模式，圍繞完成條件持續推進。
/side開啟臨時支線聊天（Side chat），在不打斷主任務的情況下提問或查進度。
/review請 Codex 審查本機未提交變更或對照基準分支；使用步驟見差異檢視（Review）。
/init掃描目前專案結構，自動產生 AGENTS.md 專案說明檔骨架。
/compact ／ /status主動壓縮目前對話的上下文；或檢視對話 ID、Token 使用率與速率限制。
/model ／ /reasoning ／ /fast選擇模型、推理強度或 Fast 速度模式；Fast 的實際用量倍率依方案與官方定價頁核對。
/fork ／ /worktree ／ /local建立聊天分支（Fork），可選擇新的 Git 工作樹（Worktree）或在本機（Local）繼續。
/approve從近期自動審查（Auto-review）拒絕紀錄選取特定動作重試一次；重試仍可能被拒絕。
/memories ／ /mcp ／ /ide-context設定此聊天是否讀寫記憶；檢視模型上下文協定（MCP）伺服器；開關整合開發環境（IDE）共享上下文。
/project ／ /usage替新聊天選擇專案；或在 ChatGPT 登入可用時開啟使用量與計費。
/cloud ／ /cloud-environment在帳號有雲端權限時切換雲端執行，或選擇已發布的雲端環境。
/pin ／ /rename ／ /archive ／ /pet釘選、重新命名、封存目前聊天；或喚出／隱藏桌面寵物（Codey）。
