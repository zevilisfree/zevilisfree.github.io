安裝與深度整合開發環境（IDE 擴充功能指南）

如果只使用 Codex 桌面版處理一般檔案，不需要先安裝程式碼編輯器。當你需要自己逐行檢視、修改程式碼或進行複雜除錯時，Codex 可直接嵌入你習慣的 IDE 中工作（詳見 官方 IDE 整合指南）：

  • 支援的五大 IDE 入口：
    • VS Code、Cursor 與 Windsurf：於擴充功能市集安裝／啟用 Codex 擴充功能後，可從左側 Activity Bar 點擊圖示，或按下 Ctrl + Shift + P（macOS 為 Cmd + Shift + P）執行 Codex: Open Codex Sidebar 開啟側邊欄並登入 ChatGPT 帳號。
    • JetBrains 系列 IDE（IntelliJ IDEA、PyCharm、WebStorm 等）與 Xcode：JetBrains 可於內建 AI Chat 選單選擇 Codex；Xcode 則可於內建 Coding Assistant 中選取 Codex 作為編碼代理。
  • 自動同步活動檔案與選取範圍（/ide-context）：在 IDE 側邊欄對話時，Codex 預設會自動感知你目前開啟的活動檔案（Active file）以及滑鼠反白選取的程式碼行範圍（Selection）（可隨時透過輸入框開關或輸入 /ide-context 切換）；你也可以在輸入框輸入 @ 模糊搜尋並引用其他檔案或近期對話。
  • IDE 內模式切換與委派至雲端（Cloud Delegation）：在 IDE 側邊欄中，可直接切換 Agent（預設工作區讀寫與執行）、Chat（純架構討論與規劃） 或 Agent (Full Access)；遇到耗時的大型重構時，還可直接在 IDE 內把任務委派給 Codex Cloud 在背景雲端執行，完成後一鍵將 Diff 拉回本機編輯器審閱。
  • Git 版本控制：用來記錄版本歷史與比對修改差異；但光裝好 Git 並不會自動替普通資料夾建立歷史，需在專案目錄中初始化 Git 儲存庫（git init）。

Git 差異檢視與程式碼審查（Code Review 三大工作流）

根據 OpenAI 官方程式碼審查文件，Codex 的程式碼審查涵蓋「本機人工 Diff 檢視」、「本機 /review 主動審查」與「雲端／GitHub PR 審查（含 Code Review 側邊欄外掛與 @codex）」三大工作流：

工作流 1：本機右側「變更（Review）」面板逐檔檢視與行內批註（Inline Comments）

  1. 開啟差異：在任務結果卡片（顯示「已編輯 N 個檔案」）按「查看變更」，或開啟專案右側的「± 變更」（差異檢視／Review）分頁面板。先看檔案清單與增刪行數，再逐一展開檔案；不要只憑 Codex 的完成摘要判斷。
  2. 選對比較範圍：想看 Codex 上一輪改了什麼，選「最新輪次（Last turn）」；想看儲存庫目前尚未暫存的改動，選「未暫存（Unstaged，預設視圖）」。面板也可切換「已暫存（Staged）」、「提交（Commit）」或「分支（Branch）」。請注意：儲存庫視圖會反映整個 Git 工作樹的變更，可能包含你自己或其他工具的改動。
  3. 行內批註（Inline Comment）精準修正：逐檔核對時，若發現某一行邏輯或命名不理想，把滑鼠移到該變更行按 + 留下行內意見；把多個檔案的行內意見都標註完後，再回聊天要求 Codex 一併處理，比用純文字描述「第幾行改什麼」精準十倍！聊天卡片上的「復原 ↶」可整批還原該輪修改，而右側面板中的「暫存（Stage）」可挑選要提交的區塊、「復原（Revert）」則會捨棄所選變更（點選前請確認範圍）。

工作流 2：在本機對話輸入 /review 請 AI 主動抓漏（三種目標）

在 Commit 或發 PR 之前，建議養成「先機器初審、再人工覆核」的雙重品管習慣：在對話框輸入 /review，可選擇三種審查目標：① 未提交變更（Uncommitted changes）、② 對照基準分支（Branch vs. Base branch）、③ 單一提交（Single commit）。Codex 會以獨立審查員視角找出潛在 Bug、未處理的例外邊界或資安風險，並只回報發現而不會擅自修改你的工作樹。

工作流 3：Code Review 側邊欄面板（PR 收件匣）與 GitHub PR @codex 雲端審查

  • 桌面版／網頁版「Code Review」專屬面板（Reviewer's Cockpit）：從最左側導覽列的 PR 審查圖示、左側「自訂 → 外掛程式」安裝 Code Review 或至「設定 → 程式設計 → 程式碼審查」設定並連結 GitHub 後，即可擁有專屬的 PR 審查收件匣（自動分類 Assigned to me、Assigned to my team、Authored by me）。點開任一 PR 即可查看 AI 變更摘要、相依 PR 堆疊（PR Stack）與 CI 狀態，並可先執行私人預審（Private Codex Review），由你確認哪些意見有價值後再點擊發佈至 GitHub，避免機器人直接在團隊 PR 洗版！
  • 在 GitHub PR 直接呼叫 @codex：符合方案資格（Plus 以上）並啟用 GitHub 整合後，可在 GitHub Pull Request 留言 @codex review 觸發一般程式碼審查，或留言 @codex security review（適用於 Pro / Business / Enterprise / Edu）執行深度資安與威脅建模審查；也可在儲存庫設定開啟建立 PR 或每次 Push 時自動審查（會自動讀取儲存庫內的 AGENTS.md 審查規則）。

交付前用一則追問核對證據

可複製的核對提示
請列出本次改動的檔案、每項要求的實際結果、執行過的測試與結果，以及尚未驗證的地方。再檢查差異與未追蹤檔案，指出任何不在我要求範圍內的修改、秘密或新增外部網址。

一次性任務提示詞：四件事說清楚

重要任務可依序寫出目標（Goal）、背景（Context）、限制（Constraints）與完成判準（Done when）。不必拘泥格式，但要讓 Codex 知道從哪裡開始、什麼不能碰、什麼結果才算完成。OpenAI 官方最佳實務

可複製的任務範例
目標：修正設定頁按下「儲存」後，重新整理會還原的問題。
背景：請先查看設定頁、儲存流程與相關錯誤；從目前專案尋找檔案。
限制：保留現有 API 格式，只修改必要檔案，不處理無關畫面。
完成判準：重現原問題、確認修正後不再發生、執行相關測試；最後列出改動與尚未驗證項目。

簡單工作可只用一兩句；需求模糊、範圍大時，先用規劃（/plan）或 grill-me 技能討論再實作。官方提示詞指南

個人化指示（Codex 指示）與輸入框預測（Tab）

跨專案通用的工作偏好可在「設定 → 個人化 → 自訂指示 → Codex 指示」編輯。如畫面說明所示，Codex 會直接編輯所選機器（如「🖥 本機」）上的全域 ~/.codex/AGENTS.md 檔案；它與專案根目錄的 AGENTS.md 是不同作用範圍。若已有個人指示，先閱讀再整合，不要直接覆寫。官方設定說明

個人化自訂指令範例
- 以臺灣繁體中文回答；指令、檔名與 API 名稱保留英文。
- 完成修改時，列出變更檔案、實際執行的檢查與未驗證項目。
- 涉及對外發送、發布或改動他人資料時，先提出可審閱的內容與影響範圍。

通用偏好應簡短、具體且長期有效；專案目錄與測試方法放專案規則，這次要做的檔案與結果留在當次聊天。文字指示不能代替沙盒或核准設定。官方自訂方式

Composer Predictions：按 Tab 鍵一鍵帶入下一步預測

當 Codex 完成一輪回覆後，輸入框會根據目前上下文自動淡色顯示預測你下一步想說的話（Composer Predictions）。如果預測符合你的想法，直接按 Tab 鍵即可轉為可編輯草稿，修改或直接送出（預測本身不會額外消耗你的方案額度）。

專案裡的 AGENTS.md 階層規則、AGENTS.override.md 與 100 行瘦身實戰法

AGENTS.md 用來記錄持續適用的專案工程慣例，例如建置與測試指令、目錄邊界、修改限制及 Code Review 檢查標準。你可以在對話框輸入 /init 自動掃描專案產生骨架，或請 Codex 先讀取現有檔案再協助擬稿。

Codex 啟動工作階段時，會依照以下由上而下的階層順序探索並合併規則（越靠近當前工作目錄 cwd 的優先權越高，預設合併上限為 32 KiB / 32,768 bytes，可透過 config.toml 的 project_doc_max_bytes 調整）：

  1. 全域規則（~/.codex/AGENTS.md）：套用到這台電腦上的所有專案（若同目錄存在 ~/.codex/AGENTS.override.md，則會直接取代全域 AGENTS.md）。
  2. 儲存庫根目錄（AGENTS.md）：定義整個專案共用的驗證指令（Test / Lint / Build）與全域權限邊界。若你的團隊原本已有其他名稱的規範檔（如 CLAUDE.md 或 TEAM_GUIDE.md），可在 config.toml 設定 project_doc_fallback_filenames = ["CLAUDE.md", "TEAM_GUIDE.md"] 作為找不到 AGENTS.md 時的自動備援檔名。
  3. 子目錄規則與同層取代檔（AGENTS.override.md）：從根目錄往當前工作目錄（cwd）的每一層子資料夾（如 apps/web/、services/api/）都可放自己的 AGENTS.md。特別注意：若某一層目錄同時存在 AGENTS.override.md 與 AGENTS.md，Codex 在該層級會直接讀取 AGENTS.override.md 並「取代（忽略）」同層的 AGENTS.md！這非常適合在重構高風險模組時，臨時放入不進 Git 的 AGENTS.override.md 強制鎖定唯讀或特殊限制，完成後再刪除。

💡 社群 × 官方驗證：AGENTS.md 高效率 100 行瘦身寫法

許多人常犯的錯誤是把好幾百行的 API 文件與風格指南全塞進根目錄 AGENTS.md，導致每一輪對話都白白消耗大量 Context Token 且稀釋模型注意力。最推薦的結構是「控制在 100 行內、驗證命令置頂、明確切分 Always / Ask First / Never 三層邊界」（複雜的長篇流程則抽離到第 9 章按需載入的 .agents/skills/）：

高效能 AGENTS.md 黃金範本（可直接複製修改）
# 專案工程規範 (AGENTS.md)

## 1. 必跑驗證指令（Verification Commands - 修改後優先執行）
- 執行單元測試：`npm test -- --watch=false`
- 型別與語法檢查：`npm run typecheck && npm run lint`
- 搜尋索引同步檢查：`python build_search_index.py --check`

## 2. 三層操作邊界（Boundaries）
- **Always（永遠自動執行）：** 修改前先閱讀目標檔案與相鄰測試；保持既有 UTF-8 與換行格式；完成時列出實際跑過的驗證結果。
- **Ask First（先停下來確認）：** 新增外部套件依賴、修改資料庫 Schema、變更公開路由或刪除既有檔案。
- **Never（絕對禁止）：** 禁止硬編碼任何 API Key、Token 或個人絕對路徑；禁止直接修改 `dist/`、`node_modules/` 或 `.git/`。

## 3. Code Review Rules（供 /review 與 GitHub @codex 自動審查使用）
- 檢查所有外部或使用者輸入是否已完成 HTML 跳脫與邊界驗證。
- 確認未引入未授權的外部網路請求或隱私資料外洩風險。

小技巧（金絲雀驗證 Canary Check）：修改 AGENTS.md 後需開啟新聊天才會重新載入；若想確認某層子目錄規則是否成功生效，可暫時在檔案末尾加一行「若讀到此規則，首次回覆開頭請標註 [AGENTS_OK]」，測試確認生效後再移除該行。官方 AGENTS.md 指南

徹底釐清：三層記憶架構（帳號記憶、專案記憶與本機 Codex 記憶庫 /memories）

根據 官方記憶文件與專案指南，系統中的「記憶（Memories）」分為三個截然不同的層次，請依資料敏感度正確使用：

記憶層次運作範圍與儲存位置隱私保護與控制方式
1. ChatGPT 帳號級記憶與寫作風格
Account Memory		在 ChatGPT 個人化／記憶設定開啟時（桌面版「設定 → 個人化 → 寫作」亦提供「參考我的寫作風格」），跨日常對話記住你的長期偏好與撰寫風格。可隨時在設定頁檢視、管理，或開啟不留紀錄的臨時對話（Temporary chat，Ctrl + Shift + N）。
2. 專案來源與記憶設定
Project context		ChatGPT 專案可共用已加入的來源和專案指示；本機專案以授權資料夾為檔案上下文。Codex CLI 與 IDE 又依各自工作目錄或工作區運作。逐一核對專案成員、可見來源、記憶和資料控制；不能把專案選項當成跨工具、跨工作區的絕對保密保證。
3. 本機 Codex 記憶庫
Local Codex Memory (/memories)		於「設定 → 個人化 → Codex 記憶」選擇目標機器（如「🖥 本機」）並開啟「啟用 Codex 記憶」後，會在工作階段閒置且剩餘速率限制充足（memories.min_rate_limit_remaining_percent）時，從對話提煉工程重點並儲存在本機 ~/.codex/memories/。自動遮蔽秘密與防外部污染：提煉時會自動掃描並遮罩（Redact）API Key 與秘密；若擔心外部網頁搜尋或 MCP 工具內容污染長期記憶，可在「設定 → 個人化 → Codex 記憶」關閉「允許從使用工具的對話中建立記憶」（對應 config.toml 的 memories.disable_on_external_context = true）或點擊「刪除 Codex 記憶」，亦可隨時在單一聊天輸入 /memories 單獨開關讀寫。

完整斜線指令（Slash Commands）與前綴符號速查表

在輸入框輸入 / 即可喚出斜線指令選單；輸入 $ 可點名呼叫技能（Skill）；輸入 @ 可點名外掛程式（Plugin）、內建瀏覽器（@Browser）、外部瀏覽器（@Edge / @Chrome）、電腦操控（@Computer）或專案檔案：

斜線指令功能說明與適用場景
/plan ／ /goal切換規劃（Plan）模式先討論並鎖定做法；或啟用目標（Goal）模式圍繞驗收條件持續推進（支援 pause / resume）。
/side（或 Ctrl+Alt+S）開啟臨時支線／側邊聊天（Side chat，反白選取文字時亦可點「在側邊聊天中提問」），在不打斷主線任務、也不汙染主對話 Context 的情況下旁路提問或查進度。
/review請 Codex 在本機審查「未提交變更」、「對照基準分支」或「單一 Commit」；詳見上方三大審查工作流。
/init自動掃描目前專案目錄結構與設定，產生 AGENTS.md 專案規範檔骨架。
/compact ／ /recap ／ /status主動壓縮目前對話的上下文；不壓縮歷史快速產生目前進度重點回顧（Recap）；或檢視對話 ID、Token 使用率與速率限制。
/model ／ /reasoning ／ /fast切換模型（Astra / 6.1 Sol / 6.1 Terra / Luna）、調整 6 階推理強度（含 Max / Ultra，桌面版快捷鍵 Ctrl+Shift+M）或切換 Fast 速度模式（2x–2.5x 倍率）。
/permissions ／ /sandbox-add-read-dir在對話中途切換權限模式（如要求核准、代我核准或唯讀）；或臨時授權沙盒讀取工作區外的特定絕對路徑。
/approve從近期自動審查（Auto-review）拒絕紀錄中選取單筆動作重試一次（僅針對該次操作，不永久放寬權限）。
/fork ／ /worktree ／ /local從當前對話建立分支至新對話（Fork），並選擇在新的隔離 Git 工作樹（Worktree）或本機目錄（Local）繼續。
/subagents ／ /hooks檢視與管理平行子代理（Subagents，右側分頁顯示為「子智慧體」）；或檢視、審查並標記信任專案的生命週期掛鉤（Hooks，亦位於「設定 → 程式設計 → 掛勾」）。
/plugins ／ /skills ／ /mcp開啟外掛程式目錄、管理已安裝技能（Skills），或檢視與啟停模型上下文協定（MCP）伺服器連線。
/memories ／ /ide-context單獨設定此聊天是否允許讀寫本機記憶；或開關 IDE 擴充功能的活動檔案與選取範圍自動同步。
/project ／ /cd ／ /pwd替新聊天選擇專案；在對話中切換或顯示當前會話的絕對工作目錄。
/cloud ／ /cloud-environment在帳號具備雲端權限（Plus 以上）時切換雲端執行，或選擇已設定的雲端容器環境。
