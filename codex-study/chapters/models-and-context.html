選擇模型、選取推理強度滑桿與進階自訂

點擊輸入框右下方的模型與推理強度按鈕（如 GPT-6 Sol 中 ⌄，快捷鍵 Ctrl + Shift + M，懸停提示為「選取推理強度」，或在對話框輸入 /model）。在桌面版中，點擊該按鈕會先彈出橫向五段圓點滑桿面板（即官方文件所稱的 Power 預設滑桿 Presets slider，上方顯示目前推理強度與模型名稱，如「中 ／ GPT-6 Sol >」）；再點擊滑桿面板上方的模型名稱（如 GPT-6 Sol >），即可展開「選取模型」清單，選擇「預設（推薦的模型組合）」或個別指定底層模型（官方文件亦將頂層預設概念分為平衡的 Power、偏向深度推理的 Smarter、偏向低延遲省額度的 Faster，以及拆開自訂的 Advanced）。

下圖是本次帳號拍攝時的「選取模型」選單；模型供應與方案權益會隨版本演進，選擇前請以當前選單及官方模型頁核對：

GPT-6.1 Terra 新模型（2026-10-27 查核）

OpenAI 於 2026-10-26 發布 GPT-6.1 Terra（模型 ID：gpt-6.1-terra），主打快速、高效率的視覺推理、精準電腦操作與自然文字撰寫。上方為舊版實拍截圖，尚未包含新模型；這項補充依據官方文件，尚未補拍新選單。

桌面版可從輸入框下方模型選單選取，Work 可在 Advanced 中選擇；實際可用性依帳號、工作區、版本與推出進度。CLI 需要 0.159.0 以上，啟動指令為 codex -m gpt-6.1-terra。若選單未出現，先確認版本與帳號權益。詳見官方模型與入口說明。

⚠️ 已退役舊模型遷移提醒（2026.10 查核）

根據 OpenAI 官方模型文件，舊世代模型如 GPT-5.5（已於 2026-10-14 正式退役）、GPT-5.4、GPT-5.4-mini 與 gpt-5.3-codex-spark 均已從 ChatGPT 登入的 Codex 中退役。若你在舊專案的 config.toml、CLI 腳本或自訂子代理設定檔中寫死了這些舊模型名稱，請立即更新遷移：將 gpt-5.4 / gpt-5.5 改為 gpt-6.1-sol（或 gpt-6-sol），將 gpt-5.4-mini 改為 gpt-6-luna（註：Enterprise / Edu 工作區若需使用 Luna，管理員須先於工作區設定啟用）。遷移時須依目標模型檢查推理設定；不要將舊模型的限制套用到新模型。GPT-6.1 Terra 的 API 支援 none，但各產品介面可選值仍以目前選單為準。

6 階推理強度（含 Max / Ultra）與速度倍率（含 Pro 專屬 Ultrafast）

在模型與推理選單（或透過 /reasoning、/fast 指令）中，推理強度（Reasoning effort）與服務速度（Speed）是兩個獨立控制的維度：

  • 基礎四階推理強度——介面顯示為「低 / 中 / 高 / 超高」（對應設定檔的 Light (Low) / Medium / High / Extra High (xhigh)）：決定模型在動手修改或回答前投入多少內部思考步驟。日常任務用「低（Light）」或「中（Medium）」即可；跨模組重構再調高至「高（High）」或「超高（Extra High）」。
  • 高階推理檔位 Max 與平行子代理 Ultra：在支援的模型與進階方案上，還提供 Max（針對單一極高難度問題投入最大深度思考時間）與 Ultra（自動啟動多個平行子代理 Subagents 同時拆解大型任務的不同部分再整合結果）。若桌面版滑桿未顯示 Ultra，可至「設定 → 組態（Configuration）」開啟 Ultra in model picker slider。
  • 三階速度模式與額度消耗倍率（Standard / Fast / Ultrafast）：速度選項只加速 Token 生成速率，不會換成更聰明或更笨的模型，但會直接乘算配額消耗速率：
    • Standard（標準速度）：基準 1x 消耗速率。
    • Fast（快速模式，可輸入 /fast 開關）：消耗速率約為標準模式的 2x 至 2.5x（依使用方案內含配額或加購點數而定）。
    • Ultrafast（極速模式，Pro $500 專屬）：支援 GPT-6 Astra Ultrafast 與 GPT-6.1 Sol Ultrafast，僅限 Pro US$500／月 級距（及符合資格之企業方案）使用；消耗速率約為標準模式的 6x（使用加購點數 Credits）至 8x（使用方案內含額度）。
進階選項開啟 Fast / Ultrafast 或高階推理前先看倍率提示

調高推理強度可能增加 Token 消耗；Fast 與 Ultrafast 的方案內含用量和加購點數倍率不同。Plus 與標準 Business 的五小時估算不適用於 Pro。先看目前模型、速度和使用量提示，再決定是否加速。官方用量與倍率說明

檢視剩餘用量、5 小時訊息估算表與超額擴充機制

在帳號選單找「剩餘用量」，或到「設定 → 使用量與帳單」查看目前方案的限制、重置時間與可用選項。下方截圖展示的是特定版本的桌面介面；五小時視窗、每週視窗與重置次數的顯示方式會依方案及版本不同，Pro 目前沒有固定五小時訊息上限。CLI 可在支援的版本使用 /status 查詢狀態；請以實際畫面與官方用量說明為準。

  • 方案限制分開看：官方目前提供 Plus 與標準 Business 的每五小時本機訊息估算，並說明每週限制也可能適用；Pro 目前沒有固定五小時訊息上限。模型、速度模式與工作區政策仍會影響可用量，請以實際使用量面板及官方定價頁為準。
  • 跨端點用量：Codex 本機訊息與雲端任務共用方案用量；Work 等代理功能及 ChatGPT for Excel 的計費適用範圍，請依當前方案與官方用量頁確認。雲端任務通常可能比本機訊息消耗更多；一般 Chat 對話的限制另看 ChatGPT 方案說明。
  • 可用重置次數（Resets）：若帳號顯示「可用重置次數」或「允許 Codex 使用重置次數」，請在使用量面板查核當前說明與剩餘數量。不要把某一版介面的觸發門檻視為所有方案都適用；不確定時關閉自動使用並手動檢查。
  • 額度用盡後的選項：Plus 與 Pro 用戶可依帳號可用功能購買額外點數；有彈性計價的 Business、Edu、Enterprise 工作區可購買工作區點數。也可使用 API Key 執行額外本機對話，並按 API 費率計費。購買與設定入口請以目前帳號介面為準。

6 個省用量的進階實戰心法（含依任務搭配模型與 Context Caching）

  1. 依任務搭配 Sol、Terra、Astra 與 Luna：多檔案開發與長程工作可用 GPT-6.1 Sol；看圖、讀取畫面、文字改寫與範圍明確的操作可試 GPT-6.1 Terra；深入分析與困難決策考慮 GPT-6 Astra；規則清楚的整理與擷取可用 GPT-6 Luna。比較相同輸入下的品質、等待時間及實際用量，再決定是否切換；操作後核對已儲存結果，圖表中的數字也須回查原始素材。
  2. 善用同工作階段快取（Context Caching），避免頻繁開空白對話重讀專案：GPT-6.1 Sol 等模型對「同一對話工作階段（Session）中已讀過的上下文」享有極高的快取折抵效率。處理同一個功能模組時，請留在同一則對話中持續推進（中途若有不相干的小問題，用 /side 支線聊天提問，完成階段性任務後用 /compact 壓縮），比每改一個小地方就開全新對話重新掃描整個儲存庫省下大量額度。
  3. 精簡提示詞與輸入素材：只附上與本次修改直接相關的檔案（可用 @檔名 精準點名）與錯誤區段，避免把整份數萬行的無關 Log 或整包歷史紀錄直接貼入對話。
  4. 先用 /plan 明確定義交付規格，再動手修改：事先說清楚目標格式、修改範圍與驗收條件，並將「必要修改」與「加分優化」分開，避免代理因需求模糊改錯方向而浪費來回重做的額度。
  5. 階層化瘦身 AGENTS.md（控制在 100 行內）：大型專案請將根目錄 AGENTS.md 精簡在 100 行以內（只放核心測試指令與全域邊界），將特定子模組規則放進子資料夾的 AGENTS.md，並將長篇標準作業流程改寫成按需載入的技能（SKILL.md），避免每一輪對話都重複消耗大量固定上下文 Token。
  6. 關閉暫時不用的 MCP 伺服器與高倍率加速：每一個啟用的 MCP 伺服器都會在背景注入工具定義並佔用上下文空間，可隨時輸入 /mcp 檢查並停用閒置連線；同時確認沒有誤開 Fast（2x–2.5x）或 Ultrafast（6x–8x）速度模式。

上下文（Context）壓縮（/compact）與進度回顧（/recap）

當聊天對話越來越長時，Codex 會自動壓縮上下文，把前面的內容整理成結構化摘要後繼續進行。你也可以養成習慣，在每完成一個小功能並完成 Git Commit 的段落點，主動在輸入框輸入 /compact 觸發壓縮；若只想快速看目前對話完成了哪些事而不壓縮歷史，則可輸入 /recap 產生重點回顧，或輸入 /status 查看目前的上下文 Token 使用率與對話 ID。

請記住：/compact 壓縮的是目前對話視窗佔用的上下文空間（讓後續推理更精準、每輪消耗更省），不是清空已消耗的帳單用量，也不是重置 5 小時配額視窗。壓縮過程中請等待它完成即可，不必反覆發送同一句話。需要跨越多次壓縮仍長期遵守的硬性要求，請寫進個人化指令或專案 AGENTS.md（第 10 章會詳細說明，也可搭配第 9 章的 SessionStart Hook 在壓縮後自動重新注入關鍵架構摘要）。
